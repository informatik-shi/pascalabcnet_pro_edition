# ABC Native prototype

Экспериментальная реализация Pascal на C++20. Это первый сквозной прототип,
а не готовый релиз PascalABC.NET. Ядро не использует .NET, Mono или Python.
Текущее состояние и план расширения описаны в
[архитектуре](../docs/native-architecture.md).
Основной редактор — Qt. Tcl/Tk сохранён как исторический эксперимент.
В готовой поставке запрещены CPython, `libpython`, Python-пакеты, `.py/.pyc/.pyd`
и запуск внешнего Python. Возможности стандартных модулей SPython переносятся на
C++ с известными до выполнения типами; мост к CPython не используется.
Служебные `.py` в `native/tests` используются разработчиком для дополнительных
проверок и в приложение не устанавливаются. Сборка CMake и упаковка Qt работают
без Python. Перед созданием ZIP упаковщик отклоняет файлы Python в поставке.
Практические различия оболочек описаны в
[сравнении редакторов](../docs/native-editor-comparison.md).

## Что работает

- `program`, `begin/end`, объявления `var`, явные типы и вывод типа из выражения.
- `integer`/`longword` 32 бита, `int64`/`uint64` 64 бита, `byte`/`shortint` 8 бит, `smallint`/`word` 16 бит, `real`/`double`, `boolean`, `char` и `string` UTF-16.
- Динамические, ступенчатые и прямоугольные двумерные массивы, записи с вложенными полями, именованные типы.
- Пользовательские функции и процедуры, рекурсия, параметры по значению и `var`,
  `Result`, присваивание имени функции и `Exit`.
- Присваивания, числовые операции, сравнения, строки и короткое замыкание `and/or`.
- `if/then/else`, `while/do`, `for/to/downto`, `repeat/until`, `foreach` по строкам, массивам и `List<T>`, `break/continue`, вложенные блоки и области видимости.
- `Write` и `Writeln` для скаляров, записей, массивов и `List<T>`; `Read` и `Readln` для скалярных переменных, включая элементы массивов и поля записей.
- `Text`/`TextFile`: назначение имени, открытие, чтение и запись скалярных значений,
  проверка конца файла, сброс буфера и закрытие.
- Первый набор `PABCSystem`, операций `Arrays`, `List<T>` и текстовых файлов
  с известными до выполнения типами элементов и аргументов (подробности ниже).
- Проверка всей программы до запуска, типизированное промежуточное представление,
  байткод и верификация типов на переходах.
- Ошибки с позицией исходника, проверяемое переполнение, лимиты исполнения и вывода.
- Ошибки выполнения одновременно на английском и русском, с одинаковым кодом и позицией в CLI и Qt.
- Редактор Qt с ночной темой по умолчанию, тёмными диалогами и подсветкой ошибок.

Идентификаторы принимают буквы Unicode BMP, подчёркивание и ASCII-цифры после
первой буквы, как правило Letter/ID исходного лексера. Регистр сравнивается по
встроенным простым таблицам Unicode 15.1, независимо от системной локали.
Имена переменных, полей, типов, параметров и функций могут быть русскими;
нормализация составных символов не выполняется. Комбинируемые знаки, цифры
других письменностей и буквы вне BMP в идентификаторах пока не допускаются.
Исходные файлы и консольный ввод/вывод используют UTF-8. Смещения диагностики
хранятся в байтах UTF-8, номера столбцов считаются в кодовых единицах UTF-16,
совпадающих с позициями редактора Qt. Строковые значения поддерживают Unicode.
Таблицы находятся в `src/unicode.hpp`; обычная сборка использует готовый C++.
Разработчик может воспроизвести их скриптом `scripts/generate-unicode.ps1` из
[UnicodeData 15.1](https://www.unicode.org/Public/15.1.0/ucd/UnicodeData.txt);
скрипт проверяет SHA-256. Уведомление: `licenses/Unicode-License.txt`.

UpperCase/LowerCase принимают char или string, UpCase/LowCase — char.
Для символа доступны ToUpper/ToLower, IsLetter/IsDigit/IsUpper/IsLower и Code
с функциональной и расширенной записью; строки поддерживают методы ToUpper/ToLower.
Используются простые таблицы Unicode 15.1: категория букв включает Lu/Ll/Lt/Lm/Lo,
цифр — Nd, верхнего и нижнего регистра — Lu и Ll. Поэтому арабская цифра ١
проходит IsDigit, но ToDigit по своему исходному контракту принимает только 0..9.
Строковые преобразования учитывают пары суррогатов, сохраняют одиночные суррогаты
и не разворачивают один символ в несколько: ß остаётся ß. Nil-строки дают E_NIL;
длинные преобразования ограничены по работе и поддерживают отмену. Правила
фиксированы независимо от локали; культурные особенности и полное совпадение
с таблицами каждой версии .NET пока не реализованы.
Переменные получают начальные нулевые значения, локальные объявления исполняются
заново при каждом входе в блок. Сравнение строк в этом прототипе порядковое по UTF-16.
Фиксированные целые поддерживают битовые not/and/or/xor и сдвиги shl/shr.

Остальные числовые типы (`single`, `decimal`), исходные модули и остальные
возможности архитектурного профиля 0.1 ещё предстоит реализовать. Неизвестный тип
не заменяется динамическим значением. Директивы компилятора отклоняются явно.

## Перенос стандартной поставки

Учёт исходных модулей ведётся в [stdlib-status.json](stdlib-status.json): перечислены
верхнеуровневые `.pas` из `bin/Lib`, состояние переноса и реализованные функции.
Сейчас частично перенесён `PABCSystem`, начат профиль массивов и коллекций.
По реестру из 100 модулей 5 перенесены частично, 93 ожидают переноса;
2 пустых модуля совместимости (`Events`, `PointRect`) завершены: их исходники
не содержат ни API, ни инициализации. Это состояние модулей, а не процент готовности функций.
`PABCSystem` подключается автоматически; `uses PABCSystem, Arrays, Collections, FilesOperations, School;`
разрешено для реализованных встроенных операций. Загрузки исходных модулей пока нет;
остальные имена модулей отклоняются явно. Разрешённое имя в `uses` не означает
переноса всех функций соответствующего исходного модуля.
Это реализация библиотечных функций на C++, а не исполнение исходного
`PABCSystem.pas` или загрузка старых `.pcu`.

Типы аргументов, выбор перегрузки и тип результата определяются до выполнения.
Один каталог скалярных сигнатур используется анализатором, верификатором и интерпретатором;
параметризованные операции получают конкретные типы из таблицы типов программы.
Например, `Sqr(integer)` возвращает `int64`; `Round/Trunc/Floor/Ceil` возвращают
`integer`. `Round` использует округление половин к чётному, независимо от режима
округления процессора; `digits` ограничен диапазоном 0–15. `ISqrt` работает точно
до `MaxInt64`. `MinReal/MinDouble` — минимальное положительное subnormal-значение,
как `real.Epsilon` в исходной библиотеке, а не точность представления около единицы.

У строк позиции начинаются с 1; длина и позиции считаются в UTF-16.
`Copy` при индексе меньше 1 начинает с первого символа, при неположительной длине
возвращает пустую строку, а слишком большой фрагмент обрезает.
`Pos/LastPos` возвращают 0 для пустой или отсутствующей подстроки.
`LastPos` с третьим аргументом ищет в префиксе, который заканчивается на этой позиции.
Поиск порядковый, без зависимости от локали, с линейным временем на повторяющемся тексте.
Разделённые суррогатные пары остаются значениями UTF-16; при выводе одиночная половина
заменяется знаком U+FFFD, без аварийного завершения. Конкатенация может собрать пару обратно.

`Trim/TrimLeft/TrimRight` удаляют только обычный пробел U+0020, как исходный
`PABCSystem`, сохраняя табуляции и неразрывные пробелы. `ReverseString` разворачивает
единицы UTF-16 целиком или в участке `(index,length)` с индексом от 1; нулевая
длина допустима, включая позицию сразу после конца строки. `CompareStr` сравнивает
строки порядково; переносимая гарантия результата — знак и ноль при равенстве.

Строки поддерживают `nil`, отличный от `''` и текста `'nil'`, с сохранением
статического типа `string`. `Write/Writeln` выводят его как `nil`; сравнения
различают пустую строку и `nil`, при упорядочении `nil` идёт первым.
Конкатенация, `Concat`, `Copy`, `LeftStr`, `RightStr` и `CompareStr` трактуют
его как пустую строку; `Length` возвращает 0. `SetLength` и `Insert` превращают
`nil` в строку, а `Delete` оставляет его без изменений. `Pos/LastPos` возвращают
0 для пустой или `nil`-подстроки; непустая подстрока в `nil` вызывает `E_NIL`.
`Trim`, `TrimLeft`, `TrimRight`, `ReverseString` и `StrToInt` для `nil` вызывают
двуязычную ошибку `E_NIL`; `StrToInt64` и `StrToReal/StrToFloat` возвращают 0.
Обычные строковые переменные, поля записей и элементы `new string[n]` получают
пустую строку, включая новые элементы после `SetLength`. Обобщённые начальные
значения в `DynArray<T>` и отсутствующие значения `AssocArray<K,V>` получают
`nil` для строк, в том числе внутри записей. Это различие проверено с оригиналом.

`StrToInt` использует Unicode-пробелы по краям, а `StrToInt64` следует правилам
.NET NumberStyles.Integer с ASCII-пробелами. Переполнение и некорректный текст
дают разные двуязычные ошибки (`E_OVERFLOW` и `E_FORMAT`). `StrToReal/StrToFloat`
поддерживают знак, экспоненту и необязательную строку десятичного разделителя.
Без неё разделитель — точка; исходный глобальный nfi также имеет точку как групповой
разделитель. Перегрузка с разделителем использует запятую для группировки, как
`NumberFormat(separator)` в исходнике. Нечисловые записи NaN/Infinity не допускаются;
переполнение остаётся ошибкой, а слишком малые значения округляются к нулю.
`FloatToStr` использует кратчайшую запись с восстановлением исходного double и
порогами обычной/экспоненциальной записи .NET 10. Глобальная смена формата чисел и
перегрузки с объектом NumberFormatInfo пока не реализованы.

`SetLength(s,n)` дополняет строку обычными пробелами, сокращает или очищает её.
Отрицательная длина вызывает двуязычную ошибку; действует общий предел 1 048 576
единиц UTF-16. `Insert(subs,s,index)` ограничивает позицию диапазоном от 1 до
`Length(s)+1`, а `Delete(s,index,count)` оставляет строку без изменений при
неположительном count или индексе вне строки. Слишком большой count обрезается
по остатку строки; вычисления границ не переполняются.
Изменяемым аргументом может быть переменная, поле записи или элемент массива типа string.
После проверки типов процедура превращается во внутреннюю типизированную операцию;
ошибка выполнения не приводит к частичной записи нового значения. Строковые копии
сохраняют прежнее значение, а вставка строки в саму себя использует исходный текст.

Ограничения совместимости опубликованы явно: прототип допускает только конечные
`real`. Там, где .NET возвращает NaN/Infinity, машина останавливается с двуязычной
ошибкой области определения или переполнения. Целочисленное переполнение проверяется.
Результаты трансцендентных функций и `Power/Cbrt` могут различаться в последних
разрядах между C++ библиотеками и .NET. Пока отсутствуют
`single`, `decimal`, `Complex`, остальные перегрузки BigInteger и большинство перегрузок над коллекциями; преобразование
регистра и остальные строковые функции ещё не перенесены.

### Массивы, записи и подпрограммы

`array of T`, `new T[n]` и `Arr(...)` создают типизированные динамические массивы.
Индексы начинаются с 0; отрицательный размер и выход за границы дают двуязычную ошибку.
Присваивание массива сохраняет общую ссылку, `Copy` создаёт отдельный массив,
а изменение длины через `SetLength` перепривязывает только переданную переменную.
Массивы массивов поддержаны. `Length(nil)` равно 0, `High(nil)` равно −1;
обращение к элементу `nil` отклоняется во время выполнения.
`Sort/SortDescending` поддерживают скалярные элементы и порядковое сравнение строк.

Записи объявляются через `type T = record ... end` и копируются по значению.
Поля могут содержать другие записи, массивы и списки; ссылочные поля сохраняют
обычную семантику ссылок. Циклические определения типов пока не допускаются.
Функции и процедуры объявляются перед главным блоком. Все тела, включая
невызываемые, проверяются до запуска. `var` требует присваиваемый аргумент точно
того же типа. Для вызовов используются отдельные кадры; предел глубины — 128.
Возврат возможен через `Result`, имя функции или `Exit(value)`.

Params допускается для последнего одномерного массива и ровно одного имени.
Лишние аргументы преобразуются к известному типу элемента и упаковываются
в массив; пустой хвост даёт пустой ненулевой массив. Точно совпадающий явно
переданный массив сохраняет ссылку, типизированный nil передаётся как nil-массив.
Записи в упакованном хвосте копируются по значению, ссылочные значения сохраняют
общие объекты. Аргументы вычисляются слева направо; рекурсивная передача готового
params-массива не создаёт второй упаковки. Метаданные проверяются верификатором.

Перед params нельзя объявлять параметры со значениями по умолчанию, как в
исходном компиляторе. Значение по умолчанию у самого params пока не поддержано.
Пример: examples/params-parameters.pas; корпус params-compat, исходный компилятор
для него не запускался. Пользовательские обобщения и разрешение перегрузок
с params остаются в плане.

Поддержаны const-параметры по значению и out-параметры. Const запрещает прямое
присваивание параметру, полям записи и элементам массива через него, ввод,
Inc/Dec, передачу этих мест как var/out и использование как переменной цикла.
Вызовы методов ссылочных объектов и запись через отдельный изменяемый alias
сохраняют обычную семантику ссылок. Типы и копирование записей такие же, как
у параметров по значению; const-функции совместимы с типизированными callbacks.

Out реализован как var: требуется изменяемый аргумент точно того же типа.
Он сохраняет начальное значение и не обнуляет его автоматически. Именно так
out_parametr преобразуется в parameter_type.var в исходном компиляторе.
Значения по умолчанию для var/out/const запрещены. Пример:
examples/const-out-parameters.pas; нативный корпус const-out-compat, без запуска
исходного компилятора.

Поддержаны завершающие параметры по значению с `:= expression`. Пропущенные
аргументы вычисляются при каждом вызове, слева направо, после явно переданных.
Типы всех значений проверяются при анализе, включая неиспользованные значения
по умолчанию. Объявление такого параметра содержит ровно одно имя; `var` и
обязательные параметры после необязательных запрещены. Выражение может вызывать
функции или создавать объекты, но непосредственно ссылаться на переменные
и параметры нельзя, как в convert_strong_to_constant_node исходного компилятора.
Вызванная функция использует область своего объявления. Рекурсивные значения
по умолчанию подчиняются общему пределу глубины вызовов.

`default(T)` возвращает типизированный ноль для чисел, False для boolean, #0
для char, nil для строк и ссылочных типов, включая Text. Поля записей обнуляются
рекурсивно; ссылочные поля становятся nil. Обычная инициализация переменных и
`new` сохраняет существующий профиль. Text допускает nil и сравнение ссылок;
вызов метода через nil даёт двуязычную E_NIL.

`new List<T>` создаёт пустой список. Тип элементов фиксируется при анализе;
`Contains` сравнивает записи по полям, массивы и списки — по ссылке.
Объявленные без инициализатора массивы и списки имеют значение `nil`;
методы списка требуют созданный объект. Фиксированные массивы и ранги выше двух,
пользовательские перегрузки, вложенные подпрограммы, замыкания
и пользовательские обобщения пока не реализованы. Объявление подпрограммы
содержит не более 16 формальных параметров. Парсер допускает до 4096 фактических
аргументов; разрешённое количество определяет сигнатура, включая params.

### Стеки и очереди Collections

После `uses Collections;` доступны `new Stack<T>` и `new Queue<T>`.
Стек возвращает последний добавленный элемент, очередь — первый. `Top` читает
элемент без удаления; `IsEmpty` проверяет пустоту. Методы без параметров
допускают запись с `()` и без скобок. Присваивание коллекции сохраняет общую
ссылку; добавление и получение записей копирует их по значению. Вложенные
коллекции и массивы сохраняют ссылочную семантику. Тип `T` известен до запуска.
Очередь использует двустороннее хранение с удалением головы без сдвига остальных элементов.

Обращение к `Top/Pop/Dequeue` пустого созданного объекта даёт `E_EMPTY`
одновременно на английском и русском. Обращение к `nil` даёт `E_NIL`.
Индексы, сортировка и свойства `Count` этих классов не поддерживаются:
они отсутствуют в соответствующих классах исходного `Collections.pas`.

`ToString`, `Print`, `Println` пока принимают только коллекции скалярных значений.
Сохраняются порядок элементов и пробел после каждого значения. В исходном модуле
`Stack.Print`, как и `Stack.Println`, переводит строку; `Queue.Print` не переводит,
`Queue.Println` переводит. Числа форматируются как при обычном выводе новой VM;
локализованное форматирование .NET и текстовое представление составных элементов
пока не перенесены. Для результата `ToString` действует строковый предел,
для печати — также общий предел вывода.

### DynArray и SimpleSet

После `uses Collections;` доступны `new DynArray<T>` и `new DynArray<T>(size)`.
Это отдельный класс исходной библиотеки: размер и ёмкость различаются. Конструктор
создаёт ёмкость `2*size+4`; `Reserve` и запись в `Capacity` только увеличивают её,
включая исходное правило «отрицательный Reserve ничего не делает».
`Resize` и запись в `Count` изменяют размер; при выходе за ёмкость выделяется
`2*newSize` ячеек. Арифметика ёмкостей проверяется на переполнение, выделение
подчиняется общему бюджету ячеек. Константы `MIN_CAP=4` и `INC_CAP_FACTOR=2`
доступны при подключённом `Collections`.

Сохраняются особенности исходника: уменьшение размера оставляет скрытые значения,
которые появляются при последующем увеличении в пределах ёмкости. Увеличение
с перераспределением обнуляет диапазон от прежнего размера до нового.
`Insert(pos,value)` принимает только позиции существующих элементов;
вставка в конец и вставка в пустой массив отклоняются. Для добавления в конец есть `Add`.
`Remove(pos)` сдвигает элементы влево; `Find(value)` возвращает первый индекс или −1.
Индекс начинается с 0; работают чтение и присваивание через `d[index]` и `d.Elem[index]`.

Индексатор `DynArray` является свойством с получением значения и записью через setter.
Записи при чтении копируются. Прямое изменение поля вида `d[i].x`, передача
`d[i]`, `Count` или `Capacity` как `var`, `Inc/Dec` и `Readln` для этих свойств пока
не поддержаны: можно прочитать значение в обычную переменную, изменить и присвоить обратно.

`new SimpleSet<T>` сохраняет порядок добавления, исключает повторы и не меняет
множество при удалении отсутствующего значения. После удаления и повторного
добавления элемент попадает в конец. Поиск линейный, как в исходной реализации.
Записи сравниваются по полям; массивы и коллекции — по ссылке. `Count` и индексатора
у исходного `SimpleSet` нет. Присваивание обоих классов сохраняет общую ссылку;
объявленные без инициализатора переменные равны `nil`.
Текстовый вывод пока ограничен скалярными элементами и следует тем же ограничениям,
что у стеков и очередей. `Print` не переводит строку, `Println` переводит.

### Ассоциативные массивы

После `uses Collections;` доступен `new AssocArray<K,V>`: типы ключа и значения
задаются независимо и проверяются до запуска. `m[key]` и `m.Elem[key]` читают
значение; присваивание заменяет существующее значение или добавляет новую пару
в конец. Поиск линейный, как в исходной библиотеке. Повторная запись сохраняет
исходное положение ключа. Присваивание самой коллекции сохраняет общую ссылку.

Чтение отсутствующего ключа не добавляет его в коллекцию и возвращает нулевое
значение типа `V`: число 0, `false`, запись с начальными полями или `nil`
для строки/массива/коллекции. Строковые поля отсутствующей записи также равны
`nil`, как при `default(V)` в исходной библиотеке.

При строковом ключе `nil` и `''` являются разными ключами. В `ToString/Print/Println`
строковый `nil` в ключе или значении даёт `E_NIL`, поскольку исходный класс
вызывает метод элемента. То же правило действует для `Stack`, `DynArray`,
`SimpleSet` и `LinkedList`; `Queue` использует конкатенацию и выводит пробел
для элемента `nil`.

Записи в ключах и значениях копируются по значению и сравниваются по полям;
массивы и коллекции — по ссылке. Поддержаны вложенные `AssocArray` и другие
составные типы, включая `nil` в ключе ссылочного типа. Индексатор является
свойством: передача результата как `var`, `Inc/Dec`, `Readln` и прямое изменение
поля записи через `m[key].field` пока не поддержаны; используется временная
переменная с последующим присваиванием обратно.

`ToString`, `Print`, `Println` пока допускают только скалярные ключи и значения.
Каждая пара записывается как `ключ пробел значение CRLF`; CRLF сохраняется на
всех ОС, как константа исходного модуля. `Println`, как и `Print`, не добавляет
дополнительный перевод строки. В Windows CLI передаёт байты вывода без
автоматического преобразования LF, чтобы строки с CRLF не превращались в CRCRLF.
Форматирование чисел и пределы текста следуют правилам остальных коллекций.
У исходного класса отсутствуют методы `ContainsKey`, `Remove` и свойства
`Count/Keys/Values`; они пока не реализованы.

### Связанные списки и узлы

После `uses Collections;` доступны `new LinkedList<T>` и
`new LinkedListNode<T>(value,prev,next)`. У списка есть свойства `First/Last`
и методы `AddFirst`, `AddLast`, `AddBefore`, `AddAfter`, `RemoveFirst`, `RemoveLast`,
`Remove`. Узел предоставляет изменяемое свойство `Value` и доступные только для
чтения `Prev/Next`. Тип узла выведен из `T` до запуска; узлы с другим типом
элемента не принимаются. Свойства не являются вызовами методов с `()`.

Пустой список возвращает `nil` в `First/Last`. Удаление из него даёт двуязычную
ошибку `E_EMPTY`; обращение к `nil` или передача `nil` в операцию над узлом — `E_NIL`.
Конструктор узла только задаёт его значение и ссылки, не меняя соседей.
Ссылки удалённого узла не очищаются, как в исходном модуле: сохранённая переменная
может продолжать читать узел и его соседей. Записи в `Value` копируются по значению;
массивы и коллекции сохраняют ссылки. Запись поля через `node.Value.field` и
передача свойства как `var` пока требуют промежуточной переменной.

VM хранит все созданные узлы до окончания исполнения; внутренние связи C++ слабые,
поэтому циклы `Prev/Next` не образуют циклов владения. Узлы учитываются в общем
бюджете ячеек значений; освобождения бюджета посреди исполнения пока нет.
Верификатор знает о ссылках узла на свой тип, отдельно проверяет пару
`LinkedList<T>/LinkedListNode<T>` и не разрешает создавать ненулевой узел в обход
типизированного конструктора. Пользовательские рекурсивные определения типов
по-прежнему не реализованы.

Сохраняются особенности исходного `Collections`: принадлежность переданного узла
списку не проверяется; операции над чужими узлами могут менять их соседей.
Циклический обход `ToString/Print/Println` останавливается общим пределом инструкций
или командой отмены. **Особенность совместимости:** исходный `ToString` заменяет
результат на каждом шаге и возвращает только последний элемент с пробелом.
Новая реализация сохраняет это поведение. Полный обход выполняется через `First`
и `Next`, либо через `Last` и `Prev`; пример приведён ниже.
Текстовый вывод пока поддерживает только скалярные элементы. `Print` не переводит
строку, `Println` переводит. `Count`, перечислители и унаследованные методы .NET
пока не реализованы.

### Односвязные узлы SingleNode

После `uses Collections;` доступен `new SingleNode<T>(data,next)`.
Конструктор принимает значение типа `T` и ссылку на следующий узел того же
`SingleNode<T>` либо `nil`. Оба свойства, `Data` и `Next`, доступны для чтения
и присваивания. Обход выполняется через `Next`; типа `Prev` и свойства `Value`
у этого класса нет. `SingleNode<T>` и `LinkedListNode<T>` — разные типы,
смешивать их ссылки нельзя. Типизация проверяется до запуска.

Присваивание узла сохраняет общую ссылку; записи в `Data` копируются по значению,
массивы и коллекции — по ссылке. Как у остальных свойств коллекций, прямое
изменение поля записи через `node.Data.field` и передача свойства как `var`
пока требуют промежуточной переменной. Обращение к свойствам `nil` вызывает
двуязычную ошибку `E_NIL`.

Разрешены перепривязка `Next`, разрыв цепочки через `nil` и ссылка на самого
себя. Узлы используют то же хранение на время исполнения со слабыми связями,
что и двусвязные списки; циклы не образуют циклов владения C++.
Пользовательский зацикленный обход останавливается общим пределом инструкций
или остановкой программы в редакторе. Все восемь классов исходного `Collections`
теперь представлены в базовом профиле; оставшиеся ограничения модуля перечислены ниже.

### Файлы

Новые файловые функции реализованы на C++ без внешнего runtime. Пути поддерживают
Unicode; относительные пути отсчитываются от текущей папки выполняемой программы.
Текст читается и записывается в UTF-8, входной UTF-8 BOM допускается.
`ReadAllLines` возвращает `array of string` и понимает LF, CRLF и CR;
`WriteAllLines` использует перевод строки текущей ОС. Предел чтения и записи — 1 МиБ.
Ошибки доступа, неверная кодировка и превышение размера получают двуязычные сообщения.
Запись заменяет содержимое существующего файла и пока не является атомарной.

`GetDir` и `GetCurrentDir` возвращают текущую папку, с круглыми скобками или без.
`ChDir` меняет её, `SetCurrentDir` делает то же с результатом `boolean`.
Рабочая папка хранится в отдельном контексте каждого выполнения, изначально
равна папке запуска и используется всеми файловыми функциями и подпрограммами.
Даже при ошибке программы папка редактора/вызывающего приложения не меняется;
следующий запуск начинает со своей исходной папки.

`MkDir` и `CreateDir` создают промежуточные каталоги; существующий каталог
считается успешным результатом. `RmDir` и `RemoveDir` удаляют только пустой каталог,
без рекурсивного удаления содержимого. `DeleteFile` удаляет существующий файл:
отсутствующий файл или каталог дают `False`. `CreateDir`, `RemoveDir` и
`SetCurrentDir` также возвращают `False` при неудаче, включая пустое имя и `nil`.
Варианты `MkDir`, `RmDir` и `ChDir` вместо этого вызывают двуязычную ошибку `E_IO`
с позицией вызова. Файловые разрешения и допустимые имена определяются ОС.
В Windows выбранную текущую папку удалить нельзя, как и в оригинальном процессе.

`ChangeFileNameExtension(name,ext)` меняет только текст имени и не переименовывает
файл на диске. Точка перед расширением необязательна; `ext=nil` убирает расширение,
`ext=''` оставляет завершающую точку. `name=nil` возвращает строковый `nil`,
пустое имя остаётся пустым. Учитываются разделители каталогов текущей ОС.
Дисковые функции и двоичные файловые дескрипторы ещё не перенесены.

`RenameFile(source,destination)` и `RenameDirectory(source,destination)` возвращают
`boolean`: занятое имя другого объекта, отсутствующий источник, пустой путь,
`nil` и отказ доступа дают `False`. Промежуточные папки назначения не создаются.
Бинарные данные сохраняются без декодирования и не ограничиваются пределом
текстового чтения. Каталоги перемещаются вместе с содержимым.
`RenameFile` для существующего файла с тем же нормализованным именем возвращает
`True`; `RenameDirectory` с тем же именем — `False`. Изменение только регистра
поддерживается системной операцией. Как и исходный `Directory.Move`,
`RenameDirectory` допускает перемещение обычного файла; `RenameFile` каталог не принимает.

Занятое имя защищено самой ОС: используются
[MoveFileExW без REPLACE_EXISTING](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw),
[renameat2 с NOREPLACE](https://man7.org/linux/man-pages/man2/rename.2.html) и
[renamex_np с EXCL](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/stdio.h).
При неподдерживаемой эксклюзивной операции каталог возвращает `False`; для файла
на Unix возможен переход к созданию жёсткой ссылки или копированию без замены.
Перенос файла между файловыми системами выполняется копированием с удалением
источника, как у [File.Move](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.move).
Такая операция не атомарна; при сбое может остаться копия, в том числе неполная.
Перемещение каталогов между файловыми системами не поддерживается.

В Windows переименование текущей папки программы и её предков возвращает `False`;
на Unix после их успешного перемещения контекст программы получает новый путь.
Папка редактора при этом не меняется. Для двух жёстких ссылок на один файл сохранены
правила ОС: Windows убирает исходное имя, Unix оставляет оба.
Файловые отказы этих двух функций возвращают `False`, как исходные обёртки;
они не превращаются в исключение выполнения.

**Отличие совместимости:** исходный `PABCSystem` на Windows по умолчанию использует
CP1251; новая переносимая реализация использует UTF-8. Перегрузки с `Encoding`,
двоичные и типизированные файлы, стандартные объекты `input/output`, перенаправление
и оставшаяся часть класса `Text` ещё не перенесены.

Файловая переменная `var f:Text` (синоним `TextFile`) сразу получает объект;
так же инициализируются поля записей, элементы обычных массивов и `Result`.
`Assign(f,name)` привязывает абсолютное имя относительно текущей папки программы.
Поздний `ChDir` эту привязку не меняет. `Reset`, `Rewrite`, `Append` открывают файл
для чтения, записи или дополнения; допустим второй аргумент с именем файла.
`OpenRead/OpenWrite/OpenAppend(name)` возвращают уже открытый `Text`.
Присваивание и передача параметра сохраняют общий объект: закрытие через одну
переменную закрывает файл для всех её копий. `new Text` также поддержан.

`Read(f,a,b)` читает значения известных типов `integer/int64/real/boolean/string`;
числа и логические значения разделяются пробельными символами Unicode.
Строка получает остаток строки, сохраняя пробелы перед ним, без перехода на следующую
строку. `Readln(f,a,b)` затем пропускает остаток текущей строки и её перевод.
Строковое чтение после конца файла возвращает пустую строку; чтение числа или
логического значения вызывает `E_EOF`. `ReadInteger/ReadInt64/ReadReal/ReadBoolean`
возвращают значение без перехода строки; `ReadlnInteger/ReadlnInt64/ReadlnReal/ReadlnBoolean`
после чтения пропускают остаток строки. `ReadString` и `ReadlnString` оба читают
строку с переходом на следующую, как исходная реализация; `ReadLexem` читает токен.
`SeekEof` пропускает пробельные символы, `SeekEoln` — только пробелы и табуляцию.
Консольные `Read` и `Readln` используют отдельный общий курсор, описанный ниже.

`Write/Writeln(f,...)` записывают скалярные значения; перевод строки соответствует
ОС. `Flush` и `Close` гарантируют передачу буфера файловой системе.
Пустые `Read(f)` и `Write(f)` ничего не делают; `Readln(f)` пропускает строку,
`Writeln(f)` записывает перевод строки. Сохранены проверенные особенности оригинала:
повторный `Rewrite` открытого писателя перемещает позицию в начало, сохраняя
отложенный буфер и существующий хвост файла. Для нового файла сначала закройте
писатель. `Append` уже открытого писателя вызывает `E_IO`.

Это начальный профиль классических текстовых файлов. Читатель хранит снимок UTF-8
размером до 1 МиБ; внешние изменения видны после нового `Reset`.
Писатель использует буфер до 1024 кодовых единиц UTF-16 и ограничен 1 МиБ на файл.
Одновременно допускается 64 открытых объекта; при завершении выполнения и при ошибке
оставшиеся объекты автоматически освобождаются с попыткой сброса буферов.
Одновременные читатель и писатель в одном объекте не поддержаны: смена режима
закрывает прежний режим. Конкурентный доступ разных объектов определяется ОС;
полная совместимость исходных правил блокировки не заявляется.
Текущий переносимый писатель `Append` требует прав и чтения, и записи файла.
Ошибки назначения имени, режима доступа и закрытия имеют код `E_IO`, исчерпание
ресурсов — `E_LIMIT`, неверные значения — `E_FORMAT/E_OVERFLOW`; сообщения содержат
английский и русский текст с позицией вызова. Прямое присваивание `nil` файловой
переменной запрещено при проверке типов; пустая ссылка из generic-контейнера даёт `E_NIL`.

Доступен объектный синтаксис `f.ReadInteger`, `f.ReadReal`, `f.ReadBoolean`,
`f.ReadString`, `f.ReadWord` и варианты `ReadlnInteger/ReadlnReal/ReadlnBoolean/ReadlnString`.
`f.Readln` пропускает остаток строки, `f.ReadToEnd` возвращает весь остаток файла
с исходными переводами строк и перемещает читатель в конец. Повторное чтение остатка
возвращает пустую строку. Как и глобальная функция, `f.ReadString` читает строку
с переходом на следующую; `f.ReadWord` соответствует `ReadLexem(f)`.

`f.Name` возвращает последнее имя в пути, `f.FullName` — полный путь, привязанный
при `Assign`, независимо от существования файла и последующего `ChDir`.
Все поддержанные методы без аргументов можно вызывать со скобками или без.
Методы `f.Reset/Rewrite/Append`, `f.Close/Flush`, `f.Eof/Eoln/SeekEof/SeekEoln`
используют те же операции и ограничения, что глобальные вызовы.
У объектных `Reset/Rewrite/Append` пока нет аргументов; вариант с именем файла
доступен через глобальную процедуру.

`f.Write(...)` и `f.Writeln(...)` соединяют значения без разделителей;
`f.Print(...)` добавляет пробел после каждого значения, включая последнее,
а `f.Println(...)` разделяет значения пробелами и завершает строку без последнего
пробела. Поддержаны до 16 скалярных аргументов с проверенными типами.
Получатель и все аргументы вычисляются слева направо один раз, до начала записи
самого вызова. Пустые `f.Write` и `f.Print` не требуют открытия файла;
пустые `f.Writeln` и `f.Println` записывают перевод строки.
Пустая ссылка вместо объекта всегда вызывает `E_NIL`.
`Name/FullName` до `Assign` и `ReadToEnd` без открытого читателя также дают `E_NIL`,
как обращение к отсутствующему внутреннему объекту в исходной реализации.
Метод `Lines` и перегрузки с `Encoding` ещё предстоит перенести.

`Erase(f)` и `f.Erase` удаляют файл с назначенным именем. Отсутствующий файл
в существующей папке не вызывает ошибки; каталог не удаляется. Поведение основано
на исходной обёртке `FileInfo.Delete` и правилах [File.Delete](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.delete).
`Rename(f,newname)` и `f.Rename(newname)` перемещают файл без замены занятого имени,
по правилам исходного [File.Move](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.move).
Это процедуры: отказ доступа, занятое имя и другие
сбои дают `E_IO` с английским и русским текстом и позицией вызова.
До `Assign` используется сообщение о неназначенном имени; пустая ссылка даёт `E_NIL`.

Переименование сохраняет прежние `f.Name/FullName`, как исходный вызов `File.Move`
без изменения `FileInfo`: для работы с новым путём нужно повторить `Assign`.
Прежнее назначенное имя берётся относительно папки во время `Assign`, а относительное
новое имя — относительно текущей папки во время `Rename`. Подпрограммы и копии
переменной сохраняют общую ссылку на объект. Для этих двух операций не требуется
декодировать содержимое: двоичные данные и файлы более 1 МиБ сохраняются.
Ограничения переноса между файловыми системами те же, что у `RenameFile` выше.

В Windows открытые `Text` текущего выполнения препятствуют удалению и перемещению
файла до `Close`, в том числе через другую переменную, `DeleteFile`, `RenameFile`
и перенос содержащего каталога. Учитывается именно открытый путь: поздний `Assign`
меняет назначенное имя, но не переносит уже открытый поток. На Unix удаление или
перемещение открытого файла разрешается ОС; уже открытый читатель сохраняет свой
снимок до закрытия. Это учёт объектов внутри выполнения; полная совместимость
блокировок между процессами и всех случаев символических ссылок пока не заявляется.

## Циклы

Доступны `for var i:=start to finish do ...` и `downto`, а также существующий
счётчик `for i:=...` и явный тип `for var i:int64:=...` / `for i:int64:=...`.
В начальном профиле счётчик имеет целый тип, `boolean` или `char`; тип выводится из
начального значения либо задаётся явно. Обе границы проверяются до запуска,
неявное сужение и вещественные границы отклоняются.

Конечная граница вычисляется один раз. Сохранён порядок исходного преобразователя:
для объявленного в заголовке счётчика сначала вычисляется начальное значение,
затем конечное; для уже существующего счётчика — конечное, затем начальное.
В первом варианте конечное выражение может видеть уже инициализированный счётчик.
Новый счётчик виден только в цикле; одноимённая внешняя переменная сохраняется.
Существующий счётчик после обычного завершения остаётся на последнем значении,
а при пустом диапазоне — на начальном. Последняя итерация не выполняет лишний
шаг, поэтому `MaxInt`, `MaxInt64` и минимальные целые не вызывают переполнения.

В теле запрещены прямое присваивание счётчику, `Inc/Dec`, чтение в него,
передача как `var`-аргумента и повторное использование как существующего счётчика
вложенного цикла. Новый одноимённый счётчик вложенного цикла допустим.
Внутри подпрограммы существующий счётчик должен быть её локальной переменной;
использование `Result` как счётчика пока отклоняется явно.

`repeat ... until condition` выполняет тело хотя бы один раз. Объявления его тела
видны в условии и не видны после цикла; их инициализаторы выполняются заново
при каждом проходе. `break` завершает ближайший цикл. `continue` переходит
к проверке условия `while`, проверке `until` или шагу счётчика `for`.
Работают вложенные циклы, выходы из подпрограмм и рекурсивные вызовы.
Лимиты исполнения, отмена, проверка байткода и двуязычные ошибки остаются общими
для всех циклов. Варианты `for step` и остальные порядковые типы
счётчика ещё предстоит перенести.

Пример: [циклы и переходы](examples/loops.pas).
Корпус [циклов](tests/fixtures/loops-compat.pas) проходит проверку ожидаемого вывода;
полная сверка этого корпуса с оригинальным компилятором пока не выполнена.

`foreach var x in source do ...` работает с динамическими/ступенчатыми массивами
и `List<T>`, а также со строками UTF-16. Допустим явный тип `foreach var x:int64 in ...` / `foreach x:int64 in ...`
или уже объявленная локальная переменная `foreach x in ...`.
Тип элемента известен до запуска; допустимы обычные числовые расширения,
сужение и несовместимые составные типы отклоняются. Новый элемент виден только
в теле цикла; существующая переменная сохраняет последнее полученное значение.
Источник вычисляется и сохраняется один раз. Его последующее переприсваивание
или `SetLength` переменной массива не меняет уже начатый обход.

Переменная обхода защищена от присваивания, `Inc/Dec`, ввода и передачи как `var`.
Записи получаются как копии; для изменения копии можно объявить переменную в теле.
Ссылки на массивы и классы сохраняются: их элементы и состояние доступны для изменения.
Изменение будущего элемента исходного массива видно при его получении.
`List<T>` проверяет версию перед следующим шагом: добавление, удаление, очистка,
запись элемента/поля записи, сортировка и заполнение дают двуязычную `E_MODIFIED`
с позицией `foreach`. Изменение объекта, на который ссылается элемент, само по себе
не меняет версию внешнего списка. `break` и выход из подпрограммы завершают обход
без дополнительной проверки версии. Пустые массивы/списки дают ноль итераций;
обход `nil` вызывает `E_NIL`. Вложенные обходы, рекурсия и `continue` поддержаны.

Последовательности, деконструкция и `foreach index`
ещё не перенесены. Классы `Collections.pas` пока не поддерживают `foreach`:
в их исходной реализации нет интерфейса перечисления.
Пример: [foreach по массиву и списку](examples/foreach.pas).
Корпус [foreach](tests/fixtures/foreach-compat.pas) проверяется по ожидаемому выводу;
его полная сверка с оригинальным компилятором пока не выполнена.

## Символы и word

`char` — одна кодовая единица UTF-16, включая отдельные суррогаты; `word` — целое
без знака от 0 до 65535. Литерал в кавычках длиной ровно одна кодовая единица
имеет тип `char`, как в исходном преобразователе PascalABC.NET. Например,
`var c:='Я'` объявляет символ, а `var s:string:='Я'` — строку. Пустой литерал
и символ вне BMP (две кодовые единицы) имеют тип `string`. Символ можно неявно
преобразовать в строку; обратное преобразование переменной строки не разрешено.
Десятичные литералы `#0`–`#65535` сохраняют также NUL и суррогаты.

Доступны `Ord`/`OrdUnicode` с результатом `word`, `Chr`/`ChrUnicode`, `Succ`/`Pred`,
явные `char(...)` и `word(...)`, `Inc/Dec`, сравнения и соединение со строками.
`Ord` для integer/int64/word сохраняет тип; для boolean возвращает integer.
Проверяются выход за границы и переполнение. `word` расширяется до integer/int64/real;
в арифметике малый тип расширяется до integer. Присваивание целой константы
в `word` проверяется до запуска, явное `word(integer/int64)` — при исполнении.
Полные правила неявного сужения остальных числовых типов пока не перенесены.

Индекс `s[1]` возвращает `char`; доступны чтение и присваивание, включая поля записей
и элементы массивов/списков строк. При изменении строки её сохранённые копии
остаются прежними. `var`-параметры, `Inc/Dec` и ввод непосредственно в `s[i]`
пока отклоняются. `foreach` строки перебирает кодовые единицы, сохраняет источник
один раз и отклоняет nil. `for/to/downto` поддерживает char и word, включая крайние
значения без лишнего последнего шага. Строковые операции сохраняют лимиты исполнения.

`Read(Text,char/word)`, `ReadChar`/`ReadlnChar` и одноимённые методы `Text` работают
без пропуска пробелов для символов. По исходнику `read(f,char)` конец файла даёт
`#65535`: это преобразованный результат `StreamReader.Read() = -1`. Суррогатная
пара, записанная двумя символами в Text, сохраняется как один символ UTF-8.
Исходные правила исследованы в `TreeConverter/TreeConversion/syntax_tree_visitor.cs`
и `bin/Lib/PABCSystem.pas`; новый [корпус](tests/fixtures/characters-compat.pas)
проверяет ожидаемый вывод, полная сверка с исходным компилятором пока не выполнена.
Работают составные литералы `'a'#10'b'` и `#55356#57101`: они образуют строку,
сохраняют NUL и отдельные суррогаты. Доступны свойство `s.Length` (для nil — E_NIL),
`StringOfChar(c,n)`, повторение `s*n`, `n*s`, `c*n`, `n*c` и `c.ToDigit`/`ToDigit(c)`.
Отрицательное количество в повторении даёт пустую строку, а в `StringOfChar` — E_RANGE,
согласно разным исходным реализациям. Повторение сохраняет порядок вычисления
операндов и проверяет лимит длины до выделения памяти. `ToDigit` принимает именно
символы `'0'..'9'`, как исходный метод; другие символы дают двуязычную E_FORMAT.
`ChrWindows/OrdWindows`, кодировки и полный набор скалярных преобразований
ещё ожидают переноса. Функции регистра и категории Unicode описаны выше.
Пример: [символы и строки](examples/characters.pas).

## Малые целые

Доступны `byte` (0–255), `shortint` (−128–127) и `smallint` (−32768–32767).
Это отдельные статические типы с представлением uint8/int8/int16 в C++, включая
поля, элементы массивов и коллекций, параметры и результаты подпрограмм.
Нулевые значения, копирование записей, сортировка и изменение элементов сохраняют тип.

Целые константы проверяются при присваивании до запуска. Явные `byte(...)`,
`shortint(...)`, `smallint(...)`, `word(...)` проверяют диапазон в исполнении.
Безопасные расширения: все малые целые в integer/int64/real,
byte в smallint/word и shortint в smallint. Арифметика и унарный минус расширяют малые значения
до integer; унарный плюс сохраняет исходный тип. Смешанный `Arr(byte(1),shortint(-2))` получает элементы smallint,
а `Arr(word(1),smallint(-2))` — integer. Неявное сужение переменных пока отклоняется.
`var` требует точного типа. Новые типы поддерживаются в `Readln`, `Read(Text,...)`,
файловой и обычной записи, `Inc/Dec`, `for/to/downto` и `foreach`.
Выход за границы, в том числе последний шаг счётчика, не допускает переполнения.

`Ord`, `Succ`, `Pred`, `Abs`, двухаргументные `Min/Max` сохраняют малый тип;
`Sign` возвращает integer. `Sqr(byte/shortint/smallint)` возвращает integer,
как исходные перегрузки. `Abs` минимального signed-значения выдаёт E_OVERFLOW
в соответствии с политикой проверяемого переполнения прототипа.
`Sqr(word)` возвращает uint64. Полная совместимость с исходными преобразованиями чисел,
generic-перегрузками и режимами переполнения не заявляется.

Пример: [малые целые](examples/small-integers.pas),
[корпус](tests/fixtures/small-integers-compat.pas) проверяет ожидаемый вывод.
Типы результатов сверены с объявлениями `bin/Lib/PABCSystem.pas`;
полная сверка нового корпуса с исходным компилятором пока не выполнена.

## Longword, uint64 и логические порядковые операции

`longword` хранит 0–4294967295, `uint64` — 0–18446744073709551615.
Десятичные литералы выше MaxInt64 и не выше MaxUInt64 получают тип uint64.
Меньшие литералы сохраняют прежний вывод integer/int64; явный тип longword
задаётся объявлением или приведением. При хранении uint64 используется нативное unsigned 64-битное значение:
точные 64 бита сохраняются в массивах, записях, параметрах, результатах и коллекциях.

Арифметика longword и его унарный минус расширяются до int64, согласно исходному
`StaticSystemLib.cs`; uint64 сохраняет тип. Проверяются сложение, вычитание,
умножение, div/mod, Inc/Dec, Succ/Pred, явные целочисленные приведения и границы циклов.
Беззнаковый унарный минус допускает 0; для ненулевого значения выдаёт E_OVERFLOW
по политике проверяемого переполнения. Inc/Dec longword используют шаг integer,
uint64 — int64; отрицательный шаг меняет направление с проверкой диапазона.

`Sqr(word/longword/uint64)` возвращает uint64 с проверкой переполнения;
`Abs`, `Ord`, `Min/Max`, `Succ/Pred` сохраняют беззнаковый тип, `Sign` даёт integer.
Min/Max с uint64 и неотрицательными целыми константами сохраняют uint64;
смешение uint64 с переменной signed-типа требует явного проверяемого приведения.
Неявное расширение longword в int64/uint64 и обоих беззнаковых типов в real доступно;
последнее допускает обычную для double потерю точности. Чтение/запись Text и Readln
принимают полный диапазон. Полные исходные правила смешанных преобразований,
битовые операции и режимы переполнения ещё не перенесены.

Добавлены типизированные константы MaxByte, MaxShortInt, MaxSmallInt, MaxWord,
MaxLongWord, MaxUInt64, NewLine, AllDelimiters, END_OF_LINE_SYMBOL и __IS_SYSTEM_MODULE,
включая доступ через PABCSystem. Пользовательская функция затеняет стандартную
константу без потери доступа по полному имени. Известное при компиляции целое
вне диапазона целевого типа выдаёт E_RANGE до исполнения.

В исходнике PABCSystem логические Succ/Pred и Inc/Dec переключают значение,
включая Succ(true) и Pred(false); это поведение сохранено. Шаг для Inc/Dec(boolean)
не принимается. Работают сравнения и for от false к true / обратно, с защитой счётчика.
Пример: [беззнаковые целые](examples/unsigned-integers.pas),
[корпус](tests/fixtures/unsigned-integers-compat.pas) проверяется по ожидаемому выводу;
полная сверка нового корпуса с исходным компилятором пока не выполнена.

## Случайные числа и массивы

`Randomize`, `Randomize(seed:integer)`, `SetRandomSeed`, `Random` без аргументов,
с верхней integer/real-границей, с парой integer/real/char-границ и `RandomReal`
реализованы на C++. Тип результата определяется по выбранной перегрузке до запуска.
Состояние принадлежит одному исполнению и разделяется его подпрограммами;
другие исполнения не меняют последовательность. При явном seed используется
совместимый вычитающий генератор из [исходника .NET 10](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Random.CompatImpl.cs).
Без seed используется xoshiro256** с начальным состоянием от системного источника
через C++ random_device. Лицензия алгоритма включена в поставку; CLR не требуется.

`Random(n:integer)` принимает n=0 и исключает правую границу. Он расходует один
seeded-отсчёт даже при n=0. `Random(a,b:integer/char)` включает обе границы,
меняет их местами при необходимости и сохраняет исходное вычисление b+1;
для integer b=MaxInt действует проверка переполнения. `Random(max:real)` использует
абсолютную верхнюю границу, real-пара исключает правую границу. `RandomReal`
по умолчанию округляет до двух знаков; отрицательное digits отключает округление.
Порядок округления и ограничения исходными a/b сохранён, включая исходное поведение
при перевёрнутых границах. Ошибки диапазонов и системного источника имеют EN/RU и позицию.

Доступны `ArrRandom` (включая defaults 10,0,100), `ArrRandomInteger` без аргументов,
с размером или размером и границами, `ArrRandomReal` с defaults и явными границами/digits,
`FillRandom(a,low,high)` и `a.FillRandom(low,high)` для integer/real-массивов.
После `uses Arrays` доступны `CreateRandomIntegerArray`, `CreateRandomRealArray`
и `FillByRandom` с исходными одномерными перегрузками и полными именами Arrays.
У Arrays integer-диапазон по умолчанию 0..99, у PABCSystem — 0..100.
Исходный Arrays.FillByRandom(real[],min,max) умножает Random на разность max−min
без прибавления min; это сохранено. FillRandom у PABCSystem использует полный real-диапазон.

Размеры и типы элементов проверяются до исполнения. Аргументы вычисляются однократно
в исходном порядке; получатель заполнения захватывается до границ. Пустые массивы
не расходуют отсчётов и не вызывают скалярные проверки диапазонов. Сохраняются
лимиты выделений и отмена исполнения во время заполнения. IntRange/RealRange/CharRange,
Random2/3, ленивые последовательности, пользовательские System.Random и экспорт rnd
ещё ожидают переноса. Новый [корпус](tests/fixtures/random-compat.pas) проверяет
ожидаемый вывод и известную seeded-последовательность; исходный Pascal-компилятор
для полного сравнения этого корпуса не запускался. Пример: [случайные массивы](examples/random-arrays.pas).

## Прямоугольные матрицы

Поддержаны `array[,] of T`, `new T[rows,cols]`, нулевые индексы `m[row,col]`,
присваивание по ссылке, var-параметры, функции, записи и коллекции с матрицами.
Ранг и элемент входят в статический тип: matrix и array одного элемента несовместимы.
Доступны Length/Length(m,dim), High (верхняя граница первого измерения),
Rank/GetLength/GetUpperBound/GetLowerBound, RowCount/ColCount и построчный foreach.
Глобальный Length(nil)=0; свойство nil.Length и запросы размеров сообщают E_NIL.

SetLength сохраняет пересечение строк/столбцов, заполняя новые ячейки начальными
значениями. Как исходное CopyWithSize, он всегда создаёт новую матрицу, даже при
тех же размерах. Старые ссылки сохраняются. Исходная матрица захватывается до
вычисления новых размеров; получатель-индекс в таком преобразовании вычисляется
дважды, как в исходном генераторе присваивания. Copy и m.Copy сохраняют форму;
записи копируются по значению, ссылочные поля сохраняют ссылки.

Arrays предоставляет CreateRandomIntegerMatrix/CreateRandomRealMatrix и
FillByRandom для двух рангов. Целая матрица по умолчанию использует 0..100,
одномерный массив — 0..99. PABCSystem предоставляет MatrRandom/MatrRandomInteger
(defaults 5,5,0,100), MatrRandomReal (5,5,0,10,2) и FillRandom.
Пустая матрица не расходует случайные отсчёты и не проверяет границы/digits в ячейках.
Range-перегрузки ещё не перенесены.

После uses Arrays доступны WriteMatrix с шириной и real-точностью, а также
m.Write/m.Writeln с разделителем. WriteMatrix оставляет пробел после каждого
элемента. Matrix.Write оставляет разделитель после каждого элемента и переводит
строку после каждого ряда; Matrix.Writeln добавляет ещё один перевод строки.
Поддержаны скаляры, записи и вложенные массивы/списки через ObjectToString.
FormatValue доступен для этих же типов. Обычная ширина — PadLeft с проверкой отрицательных
значений; real-перегрузка с digits использует abs(digits), а отрицательная ширина
выравнивает влево. Действуют пределы строки/вывода и отмена в матричных циклах.
Результат форматирования проверен нативными тестами; полная сверка версий .NET
и исходного компилятора для нового корпуса пока не выполнена.

Пример: `examples/matrices.pas`, корпус: `tests/fixtures/matrix-compat.pas`.
Фиксированные границы, ранги 3+, пользовательские интерфейсы сравнения,
исходные модули остаются в плане; Arrays ещё частичен.

### Вывод составных значений

ObjectToString, FormatValue, Write/Writeln, соответствующие методы Text,
WriteArray/WritelnArray и WriteMatrix понимают записи, массивы и List<T>
с рекурсивно поддерживаемыми статическими типами. Запись выводится как `(поле1,поле2)`,
массив/список — `[значение1,значение2]`, матрица — `[[ряд1],[ряд2]]`.
Имена полей и кавычки строк не добавляются. Nil выводится как `nil`;
пустая матрица любого размера — `[[]]`.

Сохранено различие исходных алгоритмов сокращения: массив длиной больше 100
показывает первые 99 элементов и `,...`; List длиной 101 показывается целиком,
а начиная с 102 — первые 100 и `,...`. Для матриц правило массива применяется
к каждому измерению. Общие ссылки между элементами разрешены; повтор объекта
в текущем пути рекурсии обозначается `(...)`. Строка ограничена 1 Mi UTF-16 единиц,
вывод — 1 MiB UTF-8; обход поддерживает отмену.

Все аргументы Write/Writeln вычисляются до вывода. Изменения массива последующим
аргументом видны при печати ранее переданной ссылки; ранее переданная запись
остаётся копией значения. Неподдерживаемые типы, включая пока не перенесённые
пользовательские ToString и составной вывод классов Collections, отклоняются
при проверке типов. Метаданные этих операций также проверяются verifier.

Пример: `examples/object-output.pas`, корпус: `tests/fixtures/object-output-compat.pas`.
Ожидаемый вывод сверялся с алгоритмом в bin/Lib/PABCSystem.pas и нативными тестами;
для нового корпуса исходный компилятор не запускался.

### Форматированный вывод

Write/Writeln и Print/Println принимают `значение:ширина` и `вещественное:ширина:точность`.
Используется тот же C++ FormatValue: ширина считается в UTF-16 единицах,
обычная отрицательная ширина даёт двуязычную E_RANGE, а real с точностью
поддерживает выравнивание влево отрицательной шириной. Точность берётся по модулю.
Для формы с двумя двоеточиями требуется именно вещественный исходный тип;
целое значение не преобразуется в real автоматически.

Как в исходном TreeConverter, форматирование выполняется при вычислении
аргумента до вызова вывода. Последующие аргументы уже не меняют полученную строку.
Синтаксис вызывает встроенную функцию, даже если пользователь объявил свою
FormatValue. В Text.Write/Writeln/Print/Println доступен такой же синтаксис.
Использование двоеточий в Read или обычных вызовах пока отклоняется.
Пример: `examples/formatted-output.pas`; отдельный ожидаемый корпус проверяет
консоль, файлы, вложенные значения и ширину UTF-16.

### Чтение из строки с курсором

ReadIntegerFromString, ReadRealFromString, ReadWordFromString и StringIsEmpty
принимают string и var-курсор integer с позициями от 1 в UTF-16 единицах.
Unicode-пробелы пропускаются; целое читается как префикс, слово и real —
до следующего пробела. После целого курсор стоит сразу после цифр.
StringIsEmpty пропускает пробелы и сообщает о конце строки.
Пустое слово в позиции Length+1 допустимо; некорректная позиция даёт E_BOUNDS,
nil-строка — E_NIL. Для StringIsEmpty позиция за концом строки означает True.

TryReadIntegerFromString/TryReadRealFromString дополнительно принимают
var-результат. Они проверяют целое слово и при ошибке восстанавливают курсор;
integer-результат сохраняется, real-результат становится нулём. Сохранены
совпадающие var-параметры и изменения версий List при продвижении/откате курсора.
ReadIntegerFromString использует исходное особое завершение ParseCoreFrom
сразу после распознавания MinInt. Обход строки поддерживает отмену выполнения.
Все типы получателей и результатов известны до запуска.

Пример: `examples/string-cursor.pas`, корпус: `tests/fixtures/string-cursor-compat.pas`.
Алгоритм сопоставлен с PABCSystem.pas; новый корпус проверен нативно,
без запуска исходного компилятора.

### School: числовые, строковые и логические функции

BigInteger подключён как отдельный статический тип с нулевым значением по умолчанию,
литералами `bi`, числовым конструктором и явными проверяемыми преобразованиями.
Фиксированные целые расширяются до BigInteger; обратное преобразование и real
требуют явного вызова. Поддерживаются арифметика, битовые операции и сдвиги.
Деление двух BigInteger возвращает BigInteger; смешанное `/` с обычным числом
возвращает real, вычисляя оба аргумента перед преобразованием внутри оператора.
`div` и `mod` усекают частное к нулю и сохраняют знак делимого у остатка.

Доступны Abs/Sqr/Sign/Min/Max, GCD/LCM, ISqrt и Power; BigInteger.Parse/TryParse,
Pow/Abs/GreatestCommonDivisor/Create, константы Zero/One/MinusOne и свойства
Sign/IsZero/IsOne/IsEven. Строки поддерживают ToBigInteger. Работают консольные
Read/Readln, ReadBigInteger/ReadlnBigInteger с приглашением и без, TryRead,
текстовые файлы, Str/Val, массивы, записи, кортежи, пользовательские процедуры
и реализованные коллекции. Типы и ссылки проверяются до выполнения; обычные
числовые перегрузки сохраняют приоритет над расширением к BigInteger.
BigInteger.TryParse возвращает false и записывает 0 при неверном тексте,
а TryRead при ошибке сохраняет старое значение. Ошибки и лимиты двуязычны.

Используется встроенная LibTomMath 1.3.0
с неизменяемой C++-обёрткой, без внешних DLL, загрузок при сборке и управляемой среды.
Временный предел бэкенда — 65536 бит на число. Проверяются знаковые операции,
остаток с усечением частного к нулю, битовые операции и сдвиги, степени,
целочисленный корень, НОД, десятичные/позиционные строки и преобразования.
BigInteger → real сохраняет усечение младших битов исходной .NET-реализации,
а real → BigInteger отбрасывает дробную часть. Тест `big_integer_backend`
содержит 165236 проверок; Windows Clang-проверка: `scripts/test-windows-clang.ps1`.
Версия и SHA-256 исходников указаны в `third_party/libtommath/UPSTREAM.md`,
лицензия — в `licenses/LibTomMath-Unlicense.txt`.
Новые числовые буферы учитываются в общем бюджете памяти порциями по 32 бита;
копирование неизменяемых значений разделяет хранение и не дублирует буфер.
Пример: `examples/big-integers.pas`, корпус: `tests/fixtures/big-integer-compat.pas`.
Остальные члены .NET BigInteger, культура, BigInteger-циклы
и полное сравнение с исходным компилятором пока не реализованы.

MinMax из School принимает одномерный массив или List с элементами integer,
int64, real либо BigInteger. Тип результата — кортеж из двух элементов того же типа;
доступны обычный вызов, School.MinMax и метод контейнера. Пустой контейнер
сохраняет исходные `(MaxValue,MinValue)`, для real — `(MaxValue,-MaxValue)`;
для BigInteger пустой контейнер даёт `(0,0)`. Nil вызывает E_NIL. Проход однократный, ограничен по работе, поддерживает отмену
и не расходует Random. Сигнатуры входного контейнера и результата проверяются
до исполнения. Ленивые sequence of и прочие реализации IEnumerable
пока не поддерживаются. Пример: `examples/school-minmax.pas`, корпус:
`tests/fixtures/school-minmax-compat.pas`. Сравнение с исходным компилятором
для этого корпуса пока не выполнялось.

Кортежи из 2–7 элементов имеют отдельный неизменяемый ссылочный тип. Доступны
литералы `(a,b)`, типы `(integer,string)`, Rec и квалифицированный PABCSystem.Rec,
конструктор именованного типа и чтение Item1…Item7 либо постоянного индекса от 0.
Сигнатура каждого элемента известна до исполнения. Типы кортежей объединяются
по составу; литерал при присваивании может расширить типы элементов, например
`var t:(int64,int64):=(1,2)`. Преобразование уже сохранённых кортежей разных типов
пока не реализовано. Индекс должен быть целой литеральной константой.

Кортежи по умолчанию равны nil; чтение элемента nil вызывает двуязычную E_NIL.
Элементы нельзя передать как var или изменить присваиванием/Inc. Запись внутри
кортежа копируется по значению; вложенные массивы и списки остаются общими ссылками.
Операции =/<> и List.Contains сравнивают содержимое, включая вложенные кортежи;
массивы и списки в элементах сохраняют ссылочное сравнение. Вывод рекурсивен,
как у записей, без пробелов после запятых. Семантика сверена с TupleVisitor.cs,
PABCSystem.pas и [System.Tuple](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Tuple.cs).
Деконструкция, порядок сравнения, Add/ToArray, Rest и остальные интерфейсы
пока не реализованы. Все новые сигнатуры и неизменяемость проверяет верификатор.

GCD/LCM принимают массив int64/BigInteger или перечисленные аргументы с uses School.
Тип результата совпадает с элементом массива; обычные двухаргументные вызовы сохраняют
приоритет фиксированных перегрузок PABCSystem. Явные School.GCD/School.LCM
выбирают форму School. Одно число возвращается без изменения знака, включая
MinInt64; пустой и nil-массив дают двуязычную ошибку E_RANGE.
Сохранены исходные порядок умножения до деления, повторная обработка второго
элемента и знаки LCM: School.LCM(-4,6) даёт -12, School.LCM(4,-6) — 12.
School.LCM(0,0) вызывает E_DIV_ZERO, а School.LCM(MaxInt64,MaxInt64) — E_OVERFLOW.
Статические типы массива и байткода проверяются до исполнения; циклы ограничены
по работе и поддерживают отмену. До 4096 перечисленных аргументов допускаются
при общем лимите стека. Пример: `examples/school-folds.pas`, корпус:
`tests/fixtures/school-fold-compat.pas`. Сравнение этого корпуса с исходным
компилятором пока не выполнялось. BigInteger-формы сохраняют те же знаки и порядок
вычислений, включая повторную обработку второго элемента.

НОД/НОК из School принимают два int64, в том числе с квалификацией School,
и возвращают int64. Сохранён исходный знаковый алгоритм Евклида и порядок
деления до умножения в НОК. Поэтому НОД(MinInt64,2) даёт 2,
НОК(0,MinInt64) — 0, а НОК(0,0) вызывает E_DIV_ZERO. Абсолютное значение
MinInt64 и деление/остаток MinInt64 на -1 сообщают E_OVERFLOW. НОДНОК возвращает
типизированный `(int64,int64)`, сохраняя исходный знак первого компонента:
НОДНОК(-18,30) даёт (-6,90), НОДНОК(MinInt64,0) — (MinInt64,0).
Примеры: `examples/tuples.pas`, `examples/russian-identifiers.pas`,
корпус: `tests/fixtures/unicode-identifiers-compat.pas`; локальная проверка
с исходным компилятором пока не выполнялась.

ReplaceLast(var string,source,target) заменяет последнее, в том числе перекрывающееся,
вхождение подстроки. При отсутствии совпадения получатель не записывается;
при совпадении сохраняются отдельные Delete/Insert и изменения версии List<string>.
Ссылка на получатель вычисляется один раз перед значениями остальных аргументов.

ReplaceMany(string,string,string) последовательно применяет каждую замену символа;
Translate(string,string,string) ищет первое вхождение исходного символа и переводит
его один раз. Поэтому ReplaceMany('ab','ab','bc') даёт cc, а Translate — bc.
У ReplaceMany также доступен вариант с массивами/List<string> подстрок, включая
смешанные пары этих контейнеров. В каждой паре заменяются неперекрывающиеся вхождения;
последующие пары обрабатывают уже изменённый текст. Недостающие и nil-строки замены
удаляют совпадения; пустая исходная подстрока отклоняется. Типы контейнеров и ссылок
проверяются до исполнения. Объявления IList<T> и остальные реализации интерфейса
пока требуют общего механизма интерфейсов.

Nil начального текста ReplaceMany означает пустую строку, а nil строк source/target
в символьной форме вызывает E_NIL. Translate проверяет nil исходного текста сразу,
source — только при непустом тексте, target — только при найденном исходном символе.
Эти правила сопоставлены с School.pas и
[исходником StringBuilder](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Text/StringBuilder.cs).
Поиск подстрок использует KMP с ограничением работы и проверкой отмены; размер
результата ограничен 1 Mi UTF-16 единиц. Регистр и кодовые единицы сохраняются.

ToInts64(string) и метод строки ToInts64 возвращают array of int64: разделителями
служат только пробел, TAB, CR и LF, затем применяется StrToInt64. Пустой текст даёт
пустой массив, nil — E_NIL. Imp(boolean,boolean) и метод boolean.Imp вычисляют
импликацию; аргументы, как у обычной функции, вычисляются перед её исполнением.
Все эти операции требуют uses School. Пример: `examples/school-text.pas`;
корпус: `tests/fixtures/school-text-compat.pas`. Проверяются 20449 сочетаний коротких
строк, UTF-16, nil, типы, ссылки и лимиты. Вызов исходного компилятора для этого
корпуса пока не выполнялся.

`SwapSubstr(var string,first,second)` и `string.SwapSubstr(first,second)`
меняют местами совпадения за один проход. Как в School.pas, сначала проверяется
наличие обеих буквальных подстрок, затем создаётся выражение `(first|second)`
без экранирования метасимволов. Если первая подстрока отсутствует, проверка nil
второго значения не выполняется. Одинаковые присутствующие ключи дают `E_KEY`;
совпадение, которое не равно ни одному ключу, также даёт `E_KEY`.
Получатель записывается один раз после успешной обработки всех совпадений,
включая успешный поиск без совпадений; ранний выход и ошибки его не записывают.
Пустая подстрока допустима: обмен `''` и `'a'` в строке `'a'` даёт `'aaa'`.
После пустого совпадения поиск продвигается на одну кодовую единицу UTF-16;
правило сопоставлено с
[RegexRunner .NET](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexRunner.cs).

Поиск использует встроенную статическую PCRE2 10.49 на C, 16-битный режим,
Unicode-классы и LF. Python, .NET и JIT не используются. Это ограниченный профиль
Regex: полная совместимость синтаксиса, balancing groups, культурных правил и
всех вариантов lookbehind .NET не заявляется. Полный публичный API Regex ещё
не перенесён. Ошибки выражения — `E_REGEX`, лимиты работы/памяти/результата —
`E_LIMIT`; отмена проверяется также во время поиска с возвратами.
Временные буферы движка ограничены текущим бюджетом значений, максимум 4 МиБ,
и освобождаются после вызова. Результат ограничен 1 Mi UTF-16 единиц.
Версия, SHA-256 и лицензия: `third_party/pcre2/UPSTREAM.md`,
`licenses/PCRE2-LICENCE.md`. Пример: `examples/school-swap.pas`;
нативный корпус: `tests/fixtures/school-swap-compat.pas`.

Из `PABCSystem` перенесены `IsMatch(string,pattern):boolean` и
`MatchValue(string,pattern):string`, их строковые методы и `Regex.IsMatch`.
`MatchValue` возвращает первое полное совпадение, а при отсутствии совпадения —
пустую строку. Пустые выражения допустимы; NUL и суррогаты остаются кодовыми
единицами UTF-16. Доступны настройки по умолчанию в том же профиле PCRE2;
явный `RegexOptions`, объекты `Regex`/`Match`, группы как объекты, последовательности
совпадений и делегаты замены пока не реализованы. Локальные переменные и функции
сохраняют обычные правила скрытия имён. Память, шаги и отмена поиска проверяются
через общий контекст исполнения. Пример: `examples/regex-search.pas`;
нативный корпус: `tests/fixtures/regex-search-compat.pas`.

Конструктор Arr принимает до 4096 значений при общем лимите стека байткода.
Верификатор хранит полные состояния в точках переходов, а прямые участки проходит
с одним текущим стеком. Это устраняет квадратичное копирование для длинных выражений,
сохраняя проверки типов на слияниях, циклах и в недостижимых метаданных.

Factorize/PrimeFactors, PrimeDivisors, PrimeFactorsCount, PrimeDivisorsCount,
Divisors и DivisorsCount поддерживают integer/int64, квалификацию School и
целочисленные методы. Списки сохраняют разрядность аргумента: List<integer>
или List<int64>; функции подсчёта возвращают integer. Малые целые расширяются
до integer, longword — до int64. Divizors — целочисленный псевдоним Divisors.

Для integer используются простые делители из кэша School; для int64 сохранён
порядок SQUFOF → Pollard Rho и исходные правила обработки найденного делителя.
Промежуточные целые проверяются на переполнение, квадратный корень корректируется
до точного целого значения, Pollard Rho применяет безопасное модульное умножение.
Все алгоритмы детерминированы и не расходуют состояние Random.
Большой составной делитель SQUFOF, который исходник не раскладывает дальше,
сохраняет ошибку E_FACTOR — например, для квадрата 2147483649.

Для n < 2 списки простых множителей/делителей пусты и их количества равны 0;
Divisors для таких значений возвращает [1], DivisorsCount — 1. Для int64 ниже
MinInt32 действует исходное делегирование IsPrime с checked-ошибкой переполнения.
Изменение доступного через FirstPrimes кэша учитывается целочисленными алгоритмами.
Циклы ограничены по работе и поддерживают отмену; результирующие списки учитывают
лимит памяти и изменения при foreach. Тип общего кэша проверяется и в недостижимом
байткоде. Пример: `examples/school-factors.pas`; корпус:
`tests/fixtures/school-factor-compat.pas`. Малый диапазон сравнивается с независимым
пробным делением и полным перебором делителей; проверяются также границы int64.

Digits(int64/BigInteger[,base]) и числовой метод Digits возвращают List<integer>.
По умолчанию основание равно 10; поддерживаются основания 2..MaxInt.
Отрицательное число или основание меньше 2 дают пустой список, ноль — [0].
DigitsToInt64(List<integer>[,base]), включая метод списка, выполняет обратное
накопление. Как в исходнике, он проверяет только digit < base: отрицательные
цифры разрешены, отдельной проверки диапазона основания нет, пустой список даёт 0.
В checked-профиле проверяется и последнее умножение степени основания;
поэтому, например, DigitsToInt64(Digits(MaxInt64)) сообщает E_OVERFLOW.
Nil-список и недопустимая цифра дают двуязычные ошибки.
DigitsToBigInteger поддерживает те же аргументы и методы, сохраняя проверку
только digit < base и последнее умножение степени основания. Новые числовые
буферы расходуют общий бюджет памяти; размер результата ограничен 65536 битами.

Primes(n) и Primes(m,n) возвращают List<integer> в возрастающем порядке.
Границы второй формы включаются и переставляются, если m > n. FirstPrimes(k)
сохраняет исходную семантику внутреннего списка: начальное решето содержит
4793 простых числа до 46349; небольшие запросы возвращают копию, большие —
общий изменяемый список текущего исполнения. Повторный большой запрос добавляет
числа снова, как в School.pas. Изменения через эту ссылку влияют и на Primes(m,n), IsPrime для integer и int64 в диапазоне integer.
Кэш создаётся при первом обращении и не переносится между запусками программы.
Список учитывает изменения при foreach, решёта и элементы списков расходуют общий
лимит памяти, вычисления поддерживают отмену. Внутренние циклы одного вызова
дополнительно ограничены instruction_limit единицами работы, чтобы изменение
кэша не приводило к бесконечному поиску. FirstPrimes(-1) и FirstPrimes(0)
дают пустые списки; меньшие k отклоняются как недопустимая граница среза.
Пример: `examples/school-lists.pas`; корпус: `tests/fixtures/school-list-compat.pas`.

IsPrime(integer/int64), School.IsPrime и целочисленный метод IsPrime проверяют
простоту с заранее известным типом аргумента и результата boolean. Для integer
используется пробное деление; для больших int64 — Miller–Rabin с первыми 12
простыми основаниями. Из границы сильных псевдопростых в
[работе Sorenson–Webster](https://arxiv.org/abs/1509.00864) следует точность
этого набора для всего положительного int64. Модульное умножение использует
суммы и сдвиги uint64 с проверенным диапазоном промежуточных значений.
Результат не зависит от генератора Random; длительные вычисления поддерживают отмену.

Исходный int64-вход делегирует n <= MaxInt преобразованию integer(n).
В текущем checked-профиле значения меньше MinInt32 дают E_OVERFLOW;
остальные n < 2 возвращают False. Проверки сравнивают малый диапазон с решетом,
диапазон выше MaxInt — с независимым пробным делением, а также используют
составные числа, сильные псевдопростые и
[простое 9223372036854775783](https://t5k.org/curios/page.php?number_id=10747)
у границы int64. Пример: `examples/school-primes.pas`.

После uses School доступны Bin/Oct/Hex(int64/BigInteger), School.Dec(string,base),
DecBig(string,base), ToBase(int64/BigInteger/string,base),
BinFormat(int64/BigInteger[,bytes[,split]]), PerfectSquare,
SinDegrees/CosDegrees/TanDegrees. Экспорты сохраняют принадлежность модулю;
без uses вызовы отклоняются до выполнения. ToBase и PerfectSquare также
доступны как целочисленные методы. Обычный Dec(var число) продолжает работать;
School.Dec или Dec(string,base) преобразует строку в int64.

Основание проверяется в диапазоне 2..36. Dec применяет простой верхний регистр
Unicode перед распознаванием ASCII-цифр и латинских букв; например, ſ становится S.
Все символы проверяются перед накоплением; результат сообщает
переполнение int64. Пустая строка означает ноль, пробелы и знаки отклоняются.
Bin/Oct/Hex используют модуль числа; действует проверка переполнения MinInt64.
Исходный int64 ToBase для нуля и отрицательных значений возвращает `0`.

BinFormat группирует число по байтам из восьми двоичных цифр, по умолчанию
разделённых пробелом. bytes задаёт минимальную длину, отрицательное значение
не добавляет дополнение. Nil-разделитель означает пустую строку. Эта операция
поддерживает и модуль MinInt64. Вывод ограничен 1 Mi UTF-16 единиц и поддерживает
отмену; полный квадрат проверяется без переполнения промежуточного произведения.
Тригонометрия использует общий профиль конечных real.

DecBig использует BigInteger и сохраняет проверку всех цифр до накопления,
включая Unicode-преобразование регистра. Пустая строка даёт ноль, знаки и пробелы
запрещены. ToBase(string,base) возвращает пустую строку при неудачном разборе,
а отрицательное или нулевое число — строку «0». Bin/Oct/Hex и BinFormat для
BigInteger работают с модулем числа. Форматирование по степеням двойки линейно
по числу битов. Пример: `examples/school-big-integers.pas`, корпус:
`tests/fixtures/school-big-integer-compat.pas`.

Addr32 и CalcIP из School имеют отдельные статические ссылочные типы.
Addr32 принимает десятичную запись с четырьмя октетами, непрерывную строку
из 32 двоичных цифр либо суффикс маски 1..31. Value — изменяемый десятичный
адрес; Value2 и Value10 — свойства только для чтения, string и longword.
Сохраняются начальные нули десятичных октетов. and/or/not создают новые адреса,
прибавление longword проверяет переполнение. AddrFormat и ToString формируют
представление по School.pas. Присваивание, параметры и контейнеры сохраняют
общую ссылку; изменение Value не меняет версию содержащего адрес списка.
Приватные поля и запись в свойства только для чтения недоступны из Pascal.

CalcIP принимает адрес и десятичную/двоичную маску либо byte-суффикс.
Доступны Address, Netmask, Bitmask:byte, Hosts:integer, Wildcard, Network,
Broadcast, Hostmin и Hostmax. Маска должна состоять из непрерывных единиц,
затем нулей. После конструктора изменения вложенных Addr32 не пересчитывают
остальные свойства. Для /31 Hosts=0, Hostmin=Network+1, Hostmax=Network,
оба генератора пусты. В checked-профиле /1 даёт E_OVERFLOW из-за исходного
преобразования 2^31 в integer до вычитания двух.

GenAddr выдаёт только адреса хостов, GenAddrBin — двоичные строки всего диапазона,
включая сеть и broadcast. Результаты — ленивые `sequence of Addr32` и
`sequence of string`: вызов генератора сохраняет источник, каждый foreach
создаёт независимое состояние перебора. Границы GenAddrBin фиксируются при начале
перебора; GenAddr читает Network при выдаче каждого хоста. Изменения источника
до foreach и между выдачами сохраняют правила School.pas. Повторный перебор
начинается заново; последовательность удерживает объект CalcIP после выхода
из создавшей его функции. Счётчик foreach — int64, поэтому даже полный диапазон
2^32 адресов можно начать перебирать и прервать через break без массива.

Тип `sequence of T` поддерживается в переменных, параметрах и результатах функций.
`Seq(a,b,...)` выводит общий тип T по тем же правилам, что и Arr, и возвращает
`sequence of T`. Единственный одномерный массив передаётся как params-массив:
`Seq(array)` сразу создаёт его отдельную копию. Изменение элементов исходного
массива после вызова не меняет снимок; записи копируются по значению, вложенные
ссылки сохраняются. Обычное неявное представление массива в sequence продолжает
видеть исходный массив. Пустой типизированный массив допустим, nil-массив даёт
`E_NIL`; без аргументов или только с нетипизированным nil вывести T нельзя.
Пара аргументов-массивов образует последовательность массивов; одиночная матрица
или List является одним ссылочным элементом, а не params-массивом.

`SeqFill(count,x)` возвращает ленивую `sequence of T`, где T — тип x. Сохраняется
одно значение, поэтому большой count не требует массива. Запись захватывается
по значению и при каждой выдаче копируется; ссылочные поля и ссылочные T остаются
общими. Каждый foreach начинает независимый повторный обход. Нулевой count
допустим; отрицательный count даёт двуязычный `E_RANGE` после вычисления обоих
аргументов. Count, поиск и материализация сохраняют общие лимиты работы, памяти
и отмену; большой повтор можно начать перебирать и прервать без материализации.
Доступны глобальные вызовы и квалификация PABCSystem. Явные generic-аргументы
функций и SeqGen с делегатами пока не реализованы. Пример:
`examples/sequence-factories.pas`; нативный корпус:
`tests/fixtures/sequence-factory-compat.pas`; исходный компилятор для него не запускался.

Перенесён `Range(a,b)` для integer и char: обе границы включаются, при b<a
получается пустая последовательность. Малые целые расширяются до integer;
символьный диапазон перебирает единицы UTF-16. Провайдер хранит начальное значение
и размер; повторный foreach независим, материализация выполняется только явно.
Число целых элементов вычисляется сразу в checked-профиле: если b-a+1 не помещается
в integer, вызов даёт `E_OVERFLOW`, даже без перебора. `Range(MaxInt,MaxInt)`
допустим и содержит один элемент. Минимальная integer-граница проверяется
выражением `not(MaxInt)`. Пустые integer-диапазоны разделяют один
неизменяемый объект в пределах исполнения, как исходный
[Enumerable.Empty](https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.empty).
Большой допустимый диапазон можно начать перебирать и прервать через break;
Count и общие запросы к генератору сохраняют лимит работы и отмену.
Поддерживаются глобальный вызов и PABCSystem.Range.

Добавлен Range(a,b,step) для integer и char с целым шагом: положительный шаг
перебирает вверх, отрицательный — вниз; несовпадение направления даёт пустую
последовательность. Аргументы вычисляются слева направо. Нулевой шаг даёт
двуязычный E_RANGE при начале перебора, даже если направление пустое.
Генератор хранит начало, шаг и 64-битное число элементов: диапазон от
not(MaxInt) до MaxInt можно начать перебирать без массива. После каждой
выдачи исходник выполняет checked-сложение со step, включая последнюю выдачу.
Поэтому Range(MaxInt,MaxInt,1).First успешен, а Last/Single/Count/ToArray
и foreach без break дают E_OVERFLOW при продолжении после последнего значения.
Any, успешные Contains/ElementAt и break не выполняют этот следующий шаг.
Все запросы, foreach и School.MinMax используют общую проверку продолжения;
лимиты работы, памяти и отмена сохраняются. Пример: examples/stepped-ranges.pas.
Добавлены Range(BigInteger,BigInteger) и Range(BigInteger,BigInteger,BigInteger).
Наличие BigInteger хотя бы в одном аргументе выбирает этот профиль; остальные
целые и char неявно расширяются до BigInteger. У результата статический тип
sequence of BigInteger. Границы включаются, шаг по умолчанию равен 1;
неверное направление даёт пустую последовательность. Нулевой шаг проверяется
при первом продолжении. Аргументы захватываются по значению, повторный и
вложенный foreach получают независимые курсоры.

BigInteger-генератор не вычисляет размер или разность границ: можно начать
диапазон с числом элементов больше uint64 и даже с разностью границ, не
помещающейся в нативный лимит самого BigInteger. Курсор хранит текущее число,
границу и шаг. На каждом продолжении выполняется bounded-сложение и сравнение;
учитываются лимиты работы, памяти и отмена. Last/Single/Count/ToArray/ToList
и School.MinMax завершают перебор; First/Any/успешный Contains и break могут
закончить его раньше. Лимит 65536 бит применяется и к сложению после последней
выдачи: Range(p,p,p) при p=1bi shl 65535 разрешает First и break, но полное
завершение даёт двуязычный E_LIMIT. Пример: examples/big-integer-ranges.pas.
PartitionPoints(a,b,n) и Linspace(a,b,n) возвращают sequence of real.
Первая функция выдаёт n+1 значений для n частей, вторая — n значений для n-1
частей. Границы real и счётчик integer проверяются до исполнения; обычные целые
границы расширяются до real. Нулевое/отрицательное число частей даёт двуязычный
E_RANGE при начале перебора. У Linspace вычитание n-1 выполняется при вызове:
для not(MaxInt) возникает E_OVERFLOW сразу, как в checked-профиле исходника.

Шаг h=(b-a)/n вычисляется при начале обхода, затем после каждой выдачи выполняется
r:=r+h, включая последнюю. Конец не прижимается к b: сохраняются накопленная
погрешность и потеря малого шага при больших координатах. Число элементов хранится
в 64 битах, MaxInt частей допускается без выделения массива. Повторный и вложенный
обход независимы, общие запросы, материализация и MinMax используют тот же курсор.
Нативный профиль real принимает только конечные числа: переполнение при вычислении
шага или последующем сложении даёт E_OVERFLOW; .NET NaN/Infinity не воспроизводятся.
Пример: examples/partition-points.pas.

Range(a,b,step) также поддерживает real: real-аргумент или целый аргумент,
который требует расширения до real, выбирает sequence of real при трёх аргументах.
Двухаргументного real Range в исходнике нет. При равных границах выдаётся a;
при неверном направлении получается пустая последовательность. Нулевой шаг
даёт E_RANGE при начале перебора. Ошибки десятичного преобразования, деления
и размера integer-счётчика также откладываются до начала перебора.

Нативный расчёт повторяет decimal-масштабирование исходника: коэффициент до
96 бит, масштаб 0..28, округление к ближайшему чётному, 15 значащих цифр при
преобразовании double. Преобразование адаптировано по
[Decimal.DecCalc .NET 10](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Decimal.DecCalc.cs)
под MIT; лицензия включена в пакет. Вычисляется n=Round(1/abs(decimal(step)/
(decimal(a)-decimal(b)))), затем выдаются a+i*step. Конец b включается точно,
когда нормированный последний шаг отличается от 1 не больше чем на 1e-14.
Умножение и сложение real выполняются раздельно; FMA и накопление шага не
используются. Например, Range(0,1,0.1) содержит ровно 11 элементов и заканчивается
точным 1. Очень близкие a/b могут совпасть после преобразования в decimal:
это сохраняет исходную ошибку деления на ноль. Выход за диапазон Decimal96
сообщается двуязычным E_OVERFLOW; слишком маленький десятичный шаг может дать
E_DIV_ZERO. Не вводится пользовательский тип decimal или поддержка NaN/Infinity.

План диапазона строится один раз на независимый обход без материализации.
Для десятичной арифметики временно резервируется 256 ячеек ограниченной памяти;
они возвращаются при успехе, ошибке и отмене. Работа планировщика также ограничена
instruction_limit. До первого продолжения размер не объявляется известным;
после расчёта его используют общие ограничения ToArray/ToList. Пример:
examples/real-ranges.pas; нативный корпус tests/fixtures/real-range-compat.pas.

Добавлены числовые Sum, Average, Product и PartialSum для последовательностей,
одномерных массивов и List. Типы входных элементов и результата известны до запуска:

| Операция | integer | int64 | real | BigInteger |
| --- | --- | --- | --- | --- |
| Sum | integer | int64 | real | BigInteger |
| Average | real | real | real | real |
| Product | int64 | int64 | real | BigInteger |
| PartialSum | sequence of integer | не определена в исходнике | sequence of real | sequence of BigInteger |

Sum пустого входа равен 0, Product — 1. Average пустого BigInteger-входа равен 0;
для integer/int64/real это двуязычный E_EMPTY. Обычные Sum/Average сохраняют
последовательный checked-профиль
[LINQ Reference Source](https://github.com/microsoft/referencesource/blob/main/System.Core/System/Linq/Enumerable.cs):
Sum(integer) складывает в integer, Average(integer/int64) — в int64; переполнение
промежуточной суммы не скрывается последующим уменьшением. Average(BigInteger)
складывает BigInteger, считает integer-элементы и преобразует общую сумму в real
перед делением. Product(integer) вычисляет int64-произведение. Нули не прекращают
обход Product и не скрывают последующие ошибки генератора. Real сохраняет общий
конечный профиль; NaN/Infinity пока не воспроизводятся. BigInteger ограничен
65536 битами и общим бюджетом памяти/работы.

PartialSum выдаёт накопленные суммы лениво, без промежуточного массива. Каждый
повторный или вложенный обход начинает с нуля и получает собственный курсор.
Nil источника проверяется при первом продолжении; создание PartialSum от
типизированного nil само по себе допустимо. First, удачный Contains и break могут
остановиться до следующего переполнения, Count и материализация вычисляют все
частичные суммы. Изменения массива видны во время перебора; версия List проверяется
исходным курсором, включая завершение. Частичная сумма BigInteger сохраняет
независимые неизменяемые значения. Цепочки PartialSum ограничены call_limit
(по умолчанию 128) при создании и обходе, чтобы ограничить нативную рекурсию и
глубину освобождения объектов. Превышение даёт двуязычный E_LIMIT.

Доступны вызовы Sum(a)/Average(a)/Product(a)/PartialSum(a), квалификация PABCSystem
и методы a.Sum/a.Sum() и аналогичные. Перегрузки с selector-делегатами, nullable,
малые/беззнаковые числовые последовательности остаются в плане. Пример:
examples/sequence-aggregates.pas; нативные корпуса sequence-aggregate-compat и
partial-sum-compat. Исходный компилятор для этих корпусов не запускался.

Take(count), Skip(count), TakeLast(count) и SkipLast(count=1) возвращают sequence
с тем же статически известным типом элемента. Поддержаны последовательности,
одномерные массивы и List, включая записи, строки, вложенные массивы и BigInteger.
Имена доступны глобально, через PABCSystem и как методы; явные generic-аргументы
остаются отдельным этапом; строки поддерживают адаптер sequence of char.

Take/Skip сохраняют iterator-профиль
[LINQ Reference Source](https://github.com/microsoft/referencesource/blob/main/System.Core/System/Linq/Enumerable.cs):
проверка nil при вызове, отрицательный Take даёт пустой результат, отрицательный
Skip ничего не пропускает. Take останавливает исходный курсор после нужного числа
выдач, не выполняя следующий шаг или проверку версии. Поэтому
Range(MaxInt,MaxInt,1).Take(1).Single успешен. Take(0) не открывает ненулевой
источник и не вызывает отложенные ошибки его генератора.

TakeLast/SkipLast реализуют тела из bin/Lib/PABCSystem.pas. TakeLast(count<=0)
не открывает источник, в том числе типизированный nil. При положительном count
TakeLast полностью читает источник и только потом выдаёт очередь последних
элементов. SkipLast использует ограниченное упреждение count+1; неположительный
count пропускает все исходные элементы. Nil для этих функций проверяется только
при фактическом открытии исходного курсора. Следовательно, nil.TakeLast(0).Count
равен 0, а nil.SkipLast(0).Any даёт E_NIL.

Буферы выделяют ячейки по поступлению данных и переиспользуют их: память для
скалярных элементов не растёт с общей длиной потока. Большой count не резервирует
полный объём заранее. TakeLast перестаёт проверять версию исходного List после
полного чтения; SkipLast сохраняет проверку на каждом продолжающемся шаге.
Записи копируются по значению, вложенные ссылочные поля и ссылочные элементы
остаются общими. Повторные и вложенные обходы независимы. Работа, выделения,
отмена и общая глубина композиции ограничены; Count не пропускает вычисления и
ошибки исходного генератора. Пример: examples/sequence-slices.pas; нативный корпус
sequence-slice-compat. Исходный компилятор для корпуса не запускался.

Select и Where принимают именованную пользовательскую функцию с параметром
по значению точно того же типа T и необязательным вторым параметром integer —
индексом исходного элемента от нуля. Индекс считается до фильтрации Where,
сбрасывается для каждого обхода и проверяется на переполнение. Select возвращает sequence of U
с известным типом результата U; Where требует результат boolean и сохраняет T.
Доступны методы, глобальные вызовы и квалификация PABCSystem. Источник может
быть sequence, одномерным массивом, List или строкой (T=char). Nil проверяется
при создании, выполнение функции откладывается до продвижения курсора.
Повторные и вложенные обходы независимы; повторное чтение текущего элемента
не вызывает функцию снова. Count и материализация выполняют функции полностью,
First/Take/break допускают досрочную остановку.

Функция использует общие с основной программой глобальные переменные, ввод,
вывод, генератор случайных чисел и лимиты VM. Подпрограммы, вызванные внутри
неё, работают в обычных кадрах; вложенные Select/Where и рекурсия сохраняют
стек внешнего выражения. Ошибка указывает строку внутри функции и содержит
оба языка. Записи передаются по значению, ссылочные поля сохраняют общие объекты.
Изменение открытого List выявляется при следующем шаге исходного курсора.

Лямбды, функции в переменных, захваты локальных переменных, встроенные функции
как значения пока не реализованы. Пример:
examples/sequence-callbacks.pas; корпус sequence-callback-compat, без запуска
исходного компилятора.

SelectMany принимает именованную функцию T -> sequence of U, array of U,
List<U> или string (U=char), в том числе с дополнительным integer-индексом
внешнего элемента. Вложенные результаты обходятся по очереди без общего массива.
Внутренний источник открывается после вызова функции; пустые результаты
пропускаются, nil вызывает E_NIL при фактическом открытии. До завершения
внутреннего обхода следующий внешний элемент не запрашивается.

Повторные и вложенные обходы независимы; записи копируются, ссылочные объекты
сохраняются. Изменение внутреннего List выявляется при его следующем шаге;
изменения массива видны при продолжении. Ограничены вложенность, работа,
память и отмена, в том числе при длинной цепочке пустых внутренних источников.
Перегрузки с отдельным resultSelector и first-class делегаты пока не перенесены.
Пример: examples/sequence-flatmap.pas; нативный корпус sequence-flatmap-compat.

Перегрузки Any/All/Count/First/FirstOrDefault/Last/LastOrDefault/Single/SingleOrDefault
принимают именованную функцию T -> boolean, без индекса и var. Они обходят
источник один раз; Any, All и First останавливаются при первом определяющем
результате. Last и Count читают источник до конца, Single проверяет отсутствие
второго совпадения. Пустой All равен True, Any — False, Count — 0; OrDefault
возвращают default(T). Отсутствие совпадения у First/Last/Single даёт E_EMPTY
с сообщением Sequence contains no matching element; избыток совпадений у
Single/SingleOrDefault даёт E_MANY с more than one matching element. Оба
сообщения имеют русский перевод и отличаются от запросов без предиката.

Sum/Average с именованной selector-функцией T -> integer/int64/real сводятся
к ленивому Select и обычному числовому агрегату, сохраняя порядок, побочные
эффекты, переполнения и ошибки в функции. Пустой Sum равен нулю, Average
вызывает E_EMPTY. Другие типы результата selector и first-class делегаты
остаются в плане. Пример: examples/sequence-predicates.pas; нативный корпус
sequence-predicate-compat без запуска исходного компилятора.

AsEnumerable возвращает типизированное представление массива, List или строки;
для существующей последовательности сохраняет тот же объект, включая nil.
Массивы и списки удерживаются по ссылке. Представление List проверяет версию
при обходе, а до его начала изменения допустимы.

Reverse для sequence of T создаёт ленивую последовательность: nil проверяется
при вызове, полное чтение и буферизация выполняются при первом шаге, затем
буфер выдаётся с конца. Каждый обход строит новый буфер, поэтому изменения
массива между обходами видны. Изменение исходного List после буферизации не
меняет результат. Записи копируются, ссылочные поля остаются общими; действуют
лимиты памяти, работы, отмены и глубины. Для обратного обхода массива без
изменения используйте a.AsEnumerable.Reverse. Обычный Reverse массива/List
сохраняет изменение на месте.

DefaultIfEmpty возвращает элементы непустого источника либо один default(T).
Явное запасное значение захватывается при вызове, даже если оно не понадобится.
Проверка nil выполняется сразу, открытие источника откладывается до обхода.
Ссылочные default(T) равны nil; поля записей обнуляются рекурсивно.

SequenceEqual сравнивает источники в порядке элементов без материализации,
останавливается при первом отличии или различии длин. Оба источника проверяются
на nil и открываются перед первым шагом; завершение также вызывает MoveNext,
сохраняя ошибки генераторов. Сравнение записей и кортежей структурное,
вложенных массивов/List — ссылочное, строк — по значению. Типы элементов должны
совпадать. Вариант с пользовательским comparer ещё не реализован.

Порядок обхода сверяется с
[LINQ Reference Source](https://github.com/microsoft/referencesource/blob/main/System.Core/System/Linq/Enumerable.cs).
Пример: examples/sequence-tools.pas; нативный корпус sequence-tools-compat,
пока без запуска исходного компилятора.

Concat и операторы `sequence + sequence`, `sequence + T`, `T + sequence`
создают ленивое объединение с известным типом элемента. Concat принимает также
одномерные массивы и List с точно совпадающим T; строковый Concat сохраняет
существующие перегрузки. Операнды вычисляются слева направо при создании.
Оба источника проверяются на nil сразу, но второй курсор открывается только
после завершения первого. Поэтому отложенные ошибки второго источника не
мешают чтению первого элемента; полное перечисление выполняет все проверки
завершения. Изменённый до открытия второго курсора List читается в новом
состоянии, а изменения уже открытого List вызывают E_MODIFIED.

Каждый обход имеет независимый курсор; массив не материализуется. Добавляемый
одиночный элемент захватывается при создании: запись копируется по значению,
ссылочные поля остаются общими. Цепочки ограничены глубиной, работой, выделениями
и отменой. Пример: examples/sequence-concat.pas; корпус sequence-concat-compat.
Сверка с исходным компилятором для корпуса пока не выполнена.

Строка неявно преобразуется в sequence of char. Поддержаны запросы, Count,
ToArray/ToList, Take/Skip/TakeLast/SkipLast и Concat, включая методы строки.
Одна кодовая единица UTF-16 — один char: Я🌍x содержит четыре элемента,
в том числе две отдельные суррогатные единицы. Преобразование захватывает
неизменяемое значение строки; последующая запись в исходную переменную
или её символы не меняет сохранённую последовательность. Курсоры используют
общий захват, без массива ячеек char. Его размер учитывается в лимите памяти.
Пустая строка даёт пустой ненулевой источник, nil-строка — nil-последовательность;
Length(nil) по-прежнему равен 0, а Count/ToArray(nil) дают двуязычную E_NIL.

Ограничение совместимости: отдельные преобразования одной строки создают
разные представления. Точная ссылочная идентичность строк .NET, включая
интернирование, ещё не воспроизведена. Пример: examples/string-sequences.pas;
корпус string-sequence-compat. Исходный компилятор для корпуса не запускался.

Одномерный массив и List<T> неявно преобразуются в `sequence of T` при точном
совпадении типа элемента; преобразование числового T в другой тип автоматически
не выполняется. Представление удерживает исходный контейнер, видит изменения
элементов массива и проверяет версии списка на каждом шаге, включая завершение
перебора. Nil-контейнер преобразуется в nil-последовательность. Два представления
одного контейнера сохраняют ссылочное равенство. Записи при выдаче и ToArray
копируются по значению, вложенные ссылочные объекты сохраняют общую ссылку.
`ToList` создаёт новый `List<T>` с тем же известным типом элемента из
последовательности, одномерного массива или списка. Записи копируются по значению,
а ссылочные поля продолжают указывать на те же объекты. Ячейки нового списка
получают собственного владельца, поэтому изменение его записей обнаруживается
при `foreach`, а исходный контейнер не меняет свою версию. Нет промежуточного
массива; работа и память ограничиваются общим механизмом материализации.
Доступны `ToList(s)`, `PABCSystem.ToList(s)`, `s.ToList()`/`s.ToList`, а также
`ToArray` как метод массива и списка. Nil даёт двуязычную ошибку `E_NIL`.
Пример: `examples/sequence-lists.pas`; нативный корпус:
`tests/fixtures/sequence-list-compat.pas`.
Для этих же источников доступны `Any`, `First`, `Last`, `FirstOrDefault`,
`LastOrDefault`, `ElementAt(integer)`, `ElementAtOrDefault(integer)` и
`Contains(T)`. Поддерживаются глобальные, квалифицированные `PABCSystem` и
методные вызовы. Тип результата известен до запуска: boolean для Any/Contains,
иначе тип элемента. Новые методы не меняют источник; записи возвращаются копией,
ссылочные элементы сохраняют ссылку. Существующий List.Contains сохраняет свой путь.
На массиве/List первый, последний и индексированный элементы читаются напрямую.
На генераторах поиск выдаёт предшествующие элементы с проверкой работы, памяти,
отмены и версий источника; Any/First/Contains прекращают обход при ответе.
Большую IP-последовательность можно проверить без создания массива адресов.
Пустые First/Last дают двуязычный `E_EMPTY`, неверный ElementAt — `E_BOUNDS`.
Варианты OrDefault возвращают нулевое значение T: в частности nil для строк и
ссылочных типов, нулевую запись для record. Nil-источник всегда даёт `E_NIL`,
включая ElementAtOrDefault с отрицательным индексом. Перегрузки с предикатами,
компараторами и явно заданным значением по умолчанию пока не реализованы.
Правила стандартного значения сопоставлены с
[Enumerable.FirstOrDefault](https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.firstordefault).
Пример: `examples/sequence-queries.pas`; нативный корпус:
`tests/fixtures/sequence-query-compat.pas`; исходный компилятор для него не запускался.
`Single` требует ровно один элемент, а `SingleOrDefault` возвращает стандартное
значение T при пустом источнике. Оба варианта отклоняют несколько элементов
двуязычным `E_MANY`; Single на пустом источнике даёт `E_EMPTY`.
На генераторе поиск останавливается при втором элементе, сохраняя лимиты выдачи;
на массиве/List достаточно проверить размер и прочитать единственный элемент.
Поддерживаются те же формы вызова и правила копирования T, без предикатов.
Правила пустого и неоднозначного результата сверены с
[Enumerable.SingleOrDefault](https://learn.microsoft.com/dotnet/api/system.linq.enumerable.singleordefault).
MinMax поддерживает числовые последовательности integer/int64/real/BigInteger.

Count использует размер массива/List без копирования элементов; для генераторов
выполняет ограниченный перебор. ToArray явно создаёт типизированный массив
с общим бюджетом памяти. Length сохранён как совместимый псевдоним Count.
Доступны также Count(s) и ToArray(s), включая PABCSystem и массивы/List.
Индексирование последовательностей и изменение их элементов запрещены до запуска.
Nil, ограничения памяти/работы, переполнение и отмена обрабатываются обычной VM.
Пример: `examples/school-ip-sequences.pas`, корпус:
`tests/fixtures/ip-sequence-compat.pas`.
Представления контейнеров: `examples/sequence-views.pas`, корпус:
`tests/fixtures/sequence-view-compat.pas`. Общие yield, делегаты, string-адаптер
и полный LINQ остаются в плане. Общий обход вынесен в `src/sequences.cpp`;
IP-провайдер отвечает за свои границы и формирование значений.
Неверные адреса и маски дают
двуязычные E_FORMAT/E_RANGE вместо исходного Println+Halt. Nil и переполнение
сохраняют общие E_NIL/E_OVERFLOW. Метаданные классов, свойства, сигнатуры методов
и типы результатов проверяются в байткоде до исполнения.
Пример: `examples/school-ip.pas`, корпус: `tests/fixtures/school-ip-compat.pas`.
Новый корпус проверяется нативно; исходный компилятор для него не запускался.

TrueTable(f) строит boolean-матрицу для именованной пользовательской функции
с 2..5 параметрами boolean и результатом boolean. TrueTable(n,f) принимает
именованную функцию от `array of boolean`; при n=0 вызывает её один раз с пустым
массивом. Аргументы передаются по значению. Строки перебираются от False к True,
первая переменная меняется медленнее остальных. Функция вызывается один раз
на строку; для формы с массивом каждая строка получает новый массив, а исходные
значения уже записаны в результат до вызова функции. Сигнатура известна до запуска.
Компилятор разворачивает обход в типизированные инструкции и обычные вызовы
пользовательской функции; локальные временные переменные отдельны в каждом кадре.
Лямбды, переменные-делегаты и общий механизм функциональных типов пока не реализованы.
В нативном профиле n ограничено 0..30; фактический размер матрицы и суммарные
выделения дополнительно ограничены общим бюджетом памяти. Ошибки, отмена,
глубина рекурсии и шаги пользовательской функции учитываются обычной VM.

TrueTablePrint(boolean-матрица[,filter[,names]]) выводит готовую таблицу.
По умолчанию filter=2, names='abcde'; 0 оставляет только ложные строки, 1 —
истинные, остальные значения показывают все строки. Имена колонок обрезаются
или дополняются пробелами по UTF-16; заголовок использует PrintDelimDefault.
Пустая матрица с ненулевым числом колонок сохраняет заголовок, нулевая ширина
даёт E_RANGE, nil — E_NIL. Размеры, число операций и вывод ограничены;
ошибки содержат русский и английский текст. Пример: `examples/truth-tables.pas`,
корпус: `tests/fixtures/school-truth-table-compat.pas`. Новые корпуса проверяются
нативно по ожидаемому выводу; исходный компилятор для них не запускался.

Этот блок School частичен. Культурно-зависимое преобразование регистра,
SwapSubstr, общие делегаты и ленивые последовательности остаются в плане. Новый ожидаемый корпус проверяется
нативно, исходный компилятор для него не запускался.
Пример: `examples/school-bases.pas`, корпус: `tests/fixtures/school-base-compat.pas`.

### Массивы из строки

Строковые методы PadLeft/PadRight(width[,char]), Substring(start[,count]),
Insert(start,string) и Remove(start[,count]) реализованы на C++.
Они возвращают значение, сохраняя получателя; индексы этих методов нулевые,
в отличие от s[1] и Pascal Copy/Insert/Delete. Ширина меньше текущей длины
не обрезает строку; отрицательная ширина даёт E_RANGE. Диапазоны проверяются
до копирования, неверный индекс/длина дают E_BOUNDS. Nil-получатель и nil-строка
вставки дают E_NIL; пустая строка вставки разрешена. Размеры и индексы измеряются
в UTF-16, включая отдельные суррогаты. Сохраняется порядок вычисления получателя
и всех аргументов до проверки nil. Размер результата ограничен 1048576 кодовыми
единицами. Контракт сверён с
[System.String](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/String.Manipulation.cs).
Пример: `examples/string-methods.pas`, корпус:
`tests/fixtures/string-value-method-compat.pas`; проверка с исходным компилятором
для нового корпуса пока не выполнялась.

ToWords возвращает array of string без пустых элементов. По умолчанию
разделителем служит пробел; поддержаны строка символов-разделителей, char-параметры
и array of char. Пустой набор разделителей или nil-массив char использует
Unicode-пробелы; nil-строка разделителей вызывает E_NIL. Для неоднозначного
литерала nil требуется явный тип разделителя. Правило пустого набора сверено с
[String.Manipulation в .NET 10](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/String.Manipulation.cs).
Символы-разделители сопоставляются по UTF-16 единицам через фиксированную таблицу.

ToLines разделяет CRLF, LF и CR, сохраняя пустые строки и завершающий пустой
элемент. Пустой исходник даёт массив из одной пустой строки. Unicode-разделители
строк сохраняются внутри значений, как в исходном списке разделителей PABCSystem.

ToIntegers возвращает array of integer и использует исходный разбор числовых
префиксов с Unicode-пробелами. Пустой исходник даёт пустой массив; строка только
из пробелов вызывает E_FORMAT. ToIntegers(N) сначала выделяет массив ровно N
элементов, затем считывает их; остаток строки остаётся неиспользованным.
ToIntegers(0) допускает nil-исходник. ToReals возвращает array of real,
разделяя исходник символами пробела, TAB, CR и LF; доступен строковый десятичный
разделитель. Его пустое значение проверяется и для пустого массива, давая E_RANGE.

Тип элемента и ранг результата определены до выполнения. Ограничения числа
ячеек и отмена действуют во всех обходах. Single, NumberFormatInfo и полная
сверка с исходным компилятором пока не реализованы.
Пример: `examples/string-arrays.pas`, корпус: `tests/fixtures/string-arrays-compat.pas`.

### Числовые методы string

String.ReadInteger/ReadReal/ReadWord используют var-курсор integer от нуля.
Они выполняют проверяемый сдвиг курсора на единицу, вызывают общий разбор
и присваивают итоговую позицию после успешного чтения. Ошибка сохраняет
исходный курсор метода. Увеличение MaxInt даёт E_OVERFLOW. Успешный ReadWord
в конце строки также выполняет присваивание курсора.
Доступны функциональные вызовы ReadInteger/ReadReal/ReadWord(string,var cursor).

ToInteger и ToReal возвращают число, IsInteger и IsReal — результат проверки.
Допустимы вызовы с точкой, с пустыми скобками и функциональная запись.
ToInteger(string,integer default) и ToReal(string,real default) возвращают
значение по умолчанию при ошибке преобразования; этот аргумент вычисляется
и при корректном вводе. ToReal также принимает строковый десятичный разделитель.
Перегрузка выбирается по известным типам аргументов.

Nil для ToInteger/IsInteger и ToInteger с default вызывает E_NIL.
Обычный ToReal(nil) даёт E_NIL; IsReal(nil) возвращает False,
а ToReal(nil,числовой default) возвращает переданный default.
Сохраняется профиль конечных real; перегрузки NumberFormatInfo и BigInteger
остаются в плане. Новые сценарии проверяются нативными ожидаемыми корпусами.
Пример: `examples/string-members.pas`, корпус: `tests/fixtures/string-members-compat.pas`.

### Str, Val и проверяемое преобразование строк

Str(значение,var строка) поддерживает реализованные числовые типы и string,
включая форматированный первый аргумент `Str(число:ширина:точность,строка)`.
Числа используют тот же формат nfi; переданная nil-строка остаётся nil.
Val(строка,var число,var код) поддерживает все реализованные целые типы и real:
код 0 означает успех, код 1 — ошибку формата или диапазона.

TryStrToInt, TryStrToInt64, TryStrToReal/TryStrToFloat возвращают boolean;
string.TryToInteger и string.TryToReal используют те же операции. При ошибке
integer сохраняет старое значение, остальные перегрузки записывают ноль.
Nil для integer вызывает E_NIL; для других реализованных перегрузок даёт
неуспешное преобразование с нулём. Эти различия перенесены из ParseCore и
TryParse в PABCSystem. Получатели и источник вычисляются один раз в исходном
порядке; допускаются поля, элементы массивов/List и совпадающие var-параметры.

Integer учитывает Unicode-пробелы исходного ParseCore, остальные целые —
ASCII-пробелы и завершающие NUL. Вещественный TryParse использует точку
и NumberStyles.Float без разделителей групп. Для unsigned допустим `-0`;
поведение разбора чисел дополнительно сверялось с
[Number.Parsing в .NET 10](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Number.Parsing.cs).
Сохраняется текущий профиль конечных real: NaN/Infinity не создаются.
Single, изменяемые параметры культуры и полная сверка версий .NET остаются
в плане. Новый ожидаемый корпус запускался только нативно.
Пример: `examples/string-conversions.pas`, корпус: `tests/fixtures/string-conversion-compat.pas`.

### TryRead

TryRead(var значение[,сообщение]) возвращает boolean для всех реализованных
целых типов, real и boolean. Успех записывает прочитанное значение; неверный токен,
выход за диапазон, EOF, ошибка UTF-8 или потока возвращают False и сохраняют
прежнее значение. Прочитанный токен уже потреблён, остаток строки остаётся для
последующего Read/Readln. Поддержаны поля записей, элементы массивов и List.
Успешная запись в List меняет его версию; неуспешная не прерывает foreach.

Адрес получателя и сообщение вычисляются до входа в функцию, поэтому их ошибки
не перехватываются TryRead. Получатель захватывается один раз и сохраняется,
если вычисление сообщения переназначает массив. Непустое сообщение печатается
через общий PrintDelimDefault; в отличие от ReadInteger(''), пустое сообщение
TryRead ничего не выводит. Ошибка печати подсказки также возвращает False,
оставляя вход нетронутым. Ограничения ресурсов и отмена выполнения всегда
распространяются как ошибки среды. Single пока не перенесён; прочие ограничения BigInteger указаны выше.
Пример: `examples/try-read.pas`, корпус: `tests/fixtures/try-read-compat.pas`.
Новый корпус проверен нативно; исходный компилятор не запускался.

### Print и разделитель

Print добавляет PrintDelimDefault после каждого аргумента; Println ставит его
между аргументами и переводит строку. По умолчанию это один пробел. Пустой
Print ничего не выводит, пустой Println переводит строку. Доступны формы с Text
первым аргументом и методы Text.Print/Println, обращения через PABCSystem,
скаляры и поддерживаемые составные значения.

PrintDelimDefault — статически типизированная изменяемая string-переменная;
она поддерживает обычное присваивание, строковые операции и var-параметры.
Пустая строка убирает разделители, nil выводится как `nil`. Та же переменная
задаёт разделитель после подсказок ReadInteger/ReadReal/ReadString и других
реализованных функций ввода. Все аргументы вычисляются до печати: изменение
разделителя поздним аргументом влияет на весь вызов Print/Println.

Состояние принадлежит одному выполнению и заново инициализируется перед
пользовательскими глобальными инициализаторами. Локальные переменные и routines
могут скрывать имена; PABCSystem.Print и PABCSystem.PrintDelimDefault обращаются
к встроенным объявлениям. Разворачивание params-массива object, ковариантность
ссылочных массивов и пользовательские ToString пока не реализованы.
Нативный корпус `tests/fixtures/print-compat.pas` проверяет консоль, Text,
подсказки и изменение разделителя; полного запуска корпуса на исходном
компиляторе не выполнялось. Пример: `examples/print-settings.pas`.

## Потоковый Unicode-вывод

Общий C++ ConsoleOutput сохраняет завершающий старший UTF-16 суррогат до
следующей записи. Пара собирается между Write, аргументами Writeln, итерациями
foreach, выводом Arrays/Collections и приглашениями ко вводу. Пустая запись
состояние не сбрасывает. UTF-8 выдаётся без BOM; предел вывода учитывает
фактически закодированные байты. Поэтому foreach по `🌍` снова печатает `🌍`,
хотя Pascal char представляет только один UTF-16 code unit.

Механизм состояния проверен по исходникам [Console](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Console/src/System/Console.cs)
и [StreamWriter](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/IO/StreamWriter.cs):
AutoFlush консоли не завершает кодировщик после каждой записи.
Нативная политика ошибочных последовательностей сохраняет замену на U+FFFD;
оставшийся старший суррогат завершается при выходе, также при очистке после ошибки.
Ошибка очистки не заменяет исходную ошибку программы. Ошибки C++ потоков
преобразуются в двуязычные E_INPUT/E_OUTPUT, а штатный EOF не становится ошибкой
из-за выставленных хостом exception flags. Изменяемые кодировки и полная
совместимость поведения исходного процесса при завершении остаются в плане.
Пример: `examples/unicode-output.pas`; новый native-corpus ожидаемого вывода
не запускался исходным Pascal-компилятором.

## Консольный ввод и ReadArray

Консольные `Read`/`Readln` принимают до 16 скалярных var-аргументов.
Преобразователь исходного компилятора разбивает Read(a,b) на отдельные вызовы:
ссылка на каждый получатель вычисляется один раз непосредственно перед его чтением.
Изменение первой переменной поэтому видно при вычислении второго получателя.
Read/Read() без аргументов ничего не делают; доступны Readln/Readln() без аргументов.
Readln пропускает остаток строки после последнего значения, через #10 или EOF.
Числовой ввод пропускает пробелы, табуляции, CR и LF и читает очередной токен.
Read(char) читает один UTF-16 code unit, включая пробел или перевод строки;
при EOF возвращает #65535. Read(string) читает остаток до CR/LF, оставляя перевод
строки; при вызове уже на EOF сохраняется исходный одиночный #65535.
Readln(string) использует те же правила и затем пропускает перевод строки.
Действуют прежние проверки UTF-8, числовых диапазонов, предел входной строки 1 МиБ
и отмена. Windows CLI читает stdin в бинарном режиме, чтобы CRT не менял CR/LF.

После `uses Arrays` доступен `ReadArray` для integer[], real[] и string[].
Он заполняет существующий массив и вызывает Readln в конце, включая пустой массив.
Nil сообщает ошибку до чтения. Числа могут располагаться на нескольких строках;
остаток последней строки отбрасывается. Для string[] сохраняется исходная
особенность: первый элемент получает остаток строки, остальные получают пустые
строки до финального Readln. Пример: `examples/console-input.pas`.
Сценарий `console-input-compat` проверяет общий курсор и UTF-16 на нативном
интерпретаторе; исходный компилятор для нового корпуса не запускался.
Доступны консольные ReadInteger/ReadInt64/ReadReal/ReadBoolean/ReadChar и варианты
Readln, с пустыми скобками или без них, а также со строковым приглашением.
Приглашение выводится как исходный Print: текст и PrintDelimDefault (по умолчанию пробел), даже для пустой строки;
nil выводится как `nil`. ReadString и ReadlnString читают остаток строки и
потребляют её CR/LF; оба возвращают пустую строку при EOF. ReadLexem читает токен.
Они используют тот же курсор, что Read/Readln и ReadArray. Файловые перегрузки
с аргументом Text сохраняются. Общий каталог хранит типы аргументов и результата;
контекст библиотеки предоставляет файлы, генератор, ввод и вывод с общими пределами.

Write/Writeln, включая варианты Text, вычисляют значения всех аргументов до вывода,
как исходные обычные вызовы с object/params. Исключение в позднем аргументе
возникает до печати ранних значений. Приглашения в аргументах поэтому выводятся
до внешнего Writeln. Read(...) при этом сохраняет описанное выше последовательное
разбиение. Проверено по исходникам библиотеки и преобразователя; новый корпус
консольных функций сравнивается с ожидаемым выводом без запуска исходного компилятора.
Остальные перегрузки BigInteger, деконструкция кортежей, Input/Output и полная интерактивная/перенаправленная
.NET-семантика остаются в плане.

## Битовые операции

Добавлены `not`, `and`, `or`, `xor` над integer, int64, byte, shortint,
smallint, word, longword и uint64. Операции над двумя значениями одного типа
сохраняют этот тип; совместимые разные типы расширяются до общего целого.
Сдвиги `shl` и `shr` принимают integer-счётчик. Малые целые перед сдвигом
расширяются до integer; остальные четыре типа сохраняют свою ширину.
Знаковый shr заполняет старшие биты знаком, беззнаковый — нулями.
Как и исходные IL-инструкции, сдвиги используют только младшие 5/6 бит счётчика,
включая отрицательные значения. Левый сдвиг отбрасывает вышедшие биты.
Реализация использует unsigned и bit_cast, избегая signed-overflow в C++.

Логический `xor` вычисляет оба операнда; `and`/`or` для boolean сохраняют
короткое замыкание. Приоритет: shl/shr/and вместе с умножением, or/xor вместе
со сложением. Пример: `examples/bitwise.pas`. Полная сверка смешанных
перегрузок и константных преобразований остаётся в плане; hex-литералы ещё не добавлены.

## Вывод массивов из Arrays

После `uses Arrays` доступны `WriteArray(a[,delimiter])`, `WritelnArray`,
а также `a.Write`/`a.Writeln` для одномерных массивов скалярных типов.
Разделитель по умолчанию — пробел, он выводится только между элементами.
Пустой массив не выводит элементы; Writeln добавляет перевод строки.
Глобальный WriteArray допускает типизированный nil-массив; методы у nil
сообщают `E_NIL`, поскольку исходный метод сначала обращается к Self.Rank.
Строковый nil среди элементов или в разделителе выводится как `nil`.
Получатель и разделитель вычисляются один раз слева направо; действуют
общие пределы вывода и отмена. Матричные перегрузки описаны выше;
ObjectToString составных элементов ещё не перенесён. Пример: `examples/array-output.pas`.
Новые корпуса массивов и битовых операций проверены по ожидаемому выводу;
сравнение с исходным компилятором не выполнено.

## Дополнительная математика

`GCD(integer,integer)` возвращает integer, перегрузка int64 — int64.
Знаки входов игнорируются, GCD(0,0)=0. Любой signed MinValue сообщает
переполнение, включая пару с нулём. `LCM(int64,int64)` возвращает int64,
сначала обрабатывает нулевой аргумент, затем проверяет MinValue и
переполнение произведения после деления на GCD. Поэтому LCM(MinInt64,0)=0,
но LCM(MinInt64,1) ошибочен. Перегрузки GCD/LCM для BigInteger теперь доступны.

Добавлены `Atan2(y,x)`, `Hypot(x,y)`, `Lerp(a,b,t)` и `Remap(x,a1,b1,a2,b2)`.
Hypot использует масштабирование из исходного PABCSystem, избегая
промежуточного квадрата огромных/малых значений. Lerp и Remap допускают
экстраполяцию. Сохраняется нативная политика конечных real-результатов:
Inf/NaN сообщают двуязычную ошибку, Remap с a1=b1 — `E_DIV_ZERO`.
Пример: `examples/extended-math.pas`; новый корпус ожидаемого вывода
`tests/fixtures/extended-math-compat.pas` пока не сравнивался с исходным компилятором.

## Разворот, перемешивание и обмен

Перенесены `Reverse(a)` и `Reverse(a,index,count)` для массивов и `List<T>`,
`List.Reverse`, `Reverse(var s:string)` и строковая перегрузка с index/count.
Индексы строк начинаются с единицы, массивов и списков — с нуля. Допускается
пустой диапазон на конце. Разворот строки переставляет UTF-16 code units,
включая отдельные суррогаты; исходная строка в другой переменной сохраняется.

`Shuffle(a)` и `Shuffle(list)` используют общий генератор и алгоритм
Фишера–Йетса исходного PABCSystem. Методы `a.Shuffle` и `list.Shuffle`
возвращают тот же объект. Пустые и одноэлементные коллекции не расходуют отсчёты.
Перегрузки с отдельным объектом `System.Random` пока не перенесены.

`Swap(var a,var b)` требует двух записываемых значений одного точного типа.
Поддерживаются записи, строки, ссылки на массивы и элементы коллекций.
`array.Swap(i,j)` возвращает тот же массив. Записи копируются по значению,
ячейки элементов сохраняются, аргументы вычисляются слева направо один раз.
Разворот List меняет версию даже при count=0; Shuffle меняет её при записи,
включая обмен элемента с самим собой. Foreach замечает это через `E_MODIFIED`.
Ошибочные типы и readonly-счётчики отвергаются до исполнения; nil, границы
и отмена исполнения сохраняют двуязычную диагностику. Пример:
`examples/reverse-shuffle.pas`. Новый mutation-corpus проверен нативным
интерпретатором по ожидаемому выводу; сравнение с исходным компилятором не выполнено.

## FilesOperations и пустые модули совместимости

После `uses FilesOperations;` доступны обе исходные подпрограммы:
`ReadFileToEnd(name:string):string` и `WriteStringToFile(name:string;s:string)`.
Реализация — [file_operations.cpp](src/file_operations.cpp), с общими средствами
Text для ошибок, ограничения размера, учёта открытых объектов и текущей папки программы.
Можно использовать полное имя `FilesOperations.ReadFileToEnd(name)`; оно сохраняет
доступ к библиотеке при одноимённой пользовательской функции. Локальная переменная
с именем модуля по-прежнему обозначает переменную. Проверка подключения и типов
всех аргументов выполняется до запуска.

`ReadFileToEnd` читает строки, заменяет CR/LF/CRLF на перевод строки текущей ОС
и добавляет его после каждой прочитанной строки, в том числе после последней
без перевода строки. Пустой файл даёт пустую строку. Это поведение исходного
`StringBuilder.AppendLine`, поэтому подпрограмма отличается от `ReadAllText`.
`WriteStringToFile` перезаписывает файл и сохраняет переданные переводы строк;
nil записывается как текст `nil`, поскольку исходник вызывает `Write(Text,object)`.
Файлы UTF-8, ограничение размера 1 МиБ, нормализованная строка также ограничена 1 МиБ.
Совместимость с исходной кодировкой CP1251 и всеми правилами совместного открытия
ещё не заявляется, поэтому модуль остаётся частичным в реестре.

`uses Events, PointRect;` разрешён: оба поставляемых исходника содержат пустой
модуль без экспортов и инициализации. Новые функции и типы им не добавляются.
Пример: [FilesOperations](examples/file-operations.pas),
[корпус](tests/fixtures/file-operations-compat.pas) проверяет ожидаемый вывод;
полная сверка нового корпуса с исходным компилятором пока не выполнена.

## Что ещё не перенесено

Из 100 верхнеуровневых исходных модулей завершены только два пустых модуля совместимости.
`PABCSystem`, профиль `Arrays`, `Collections` и `FilesOperations` поддержаны частично.
Встроенный `List<T>` и начальные реализации `Stack<T>/Queue<T>/DynArray<T>/SimpleSet<T>/AssocArray<K,V>/LinkedList<T>`
с `LinkedListNode<T>` и `SingleNode<T>` уже работают.
Число реализованных функций не является процентом готовности всей среды.

- Язык и типы: single/decimal, hex-литералы, фиксированные массивы и ранги 3+,
  расширенные возможности подпрограмм, исходные модули, foreach по последовательностям,
  for step, исключения и обобщения.
- Базовая библиотека: оставшиеся возможности `Text`, двоичные файлы, кодировки, случайные числа,
  остальные преобразования и строки, словари, остальные разновидности множеств и последовательности.
- Стандартные модули: остальная часть Arrays и оставшиеся возможности
  Collections.pas; PABCExtensions, School, NumLibABC и другие.
- Графика и учебные исполнители: GraphABC, Robot, Turtle и соответствующие окна Qt.
- SPython и его библиотеки: будущий отдельный frontend и собственные C++ реализации;
  CPython и готовые Python-пакеты в приложение не включаются.
- Редактор: несколько документов, завершение имён, переход к ошибке, отладчик;
  ещё нужна проверка готовых редакторов и пакетов на Linux/macOS.

## Сборка ядра

Нужны CMake 3.24+, Ninja и компилятор с C++20. В Windows команды выполняются
из среды инструментов MSVC; подойдут также Clang с MSVC и подходящий MinGW.

```sh
cd native
cmake --preset core
cmake --build --preset core
ctest --preset core
```

Без Ninja можно выбрать стандартный генератор своей платформы:

```sh
cmake -S native -B native/build/default -DBUILD_TESTING=ON
cmake --build native/build/default --config Release
ctest --test-dir native/build/default -C Release --output-on-failure
```

Проверка от 29 октября 2026 года: MSVC Release — 4167 проверок ядра и 83 теста
CTest вместе с Qt; Clang 22 без санитайзера также проверен. Дополнительный локальный
прогон Clang 22/AddressSanitizer на Windows не завершён: обработчик исключений
аварийно останавливается, в том числе в отдельной минимальной программе с
`catch` и выбрасыванием нового исключения без вызовов интерпретатора.
Обычная сборка этого примера проходит. В GitHub Actions для коммита 568b0d29c
успешны Linux Release, Ubuntu ASan/UBSan и Windows Release; macOS в этом
запуске отменён, успешная проверка macOS пока не заявляется. Эти задания проверяют ядро без Qt. Успешная проверка ASan на Windows пока
не заявляется; отдельная задача CI проверяет ASan/UBSan на Ubuntu.

## Запуск

В каталоге сборки исполнимый файл называется `abc` (`abc.exe` на Windows).
Для генераторов Visual Studio он находится внутри `Release/` или `Debug/`.

```sh
abc check examples/sum.pas
abc run examples/sum.pas
abc run examples/sum.pas --max-instructions=1000000
```

Код возврата: 0 — успех, 1 — ошибка программы или лимита, 2 — ошибка запуска,
параметров или чтения файла. По умолчанию действует лимит 10 миллионов инструкций,
1 МиБ вывода, 1 МиБ исходника и входной строки. Конкатенация ограничивает строку
одним миллионом кодовых единиц UTF-16. Это ограничения прототипа, а не ОС-песочница.
Дополнительно действует общий бюджет 1 048 576 создаваемых ячеек значений
(элементы, поля записей и локальные переменные кадров); освобождение памяти
не возвращает этот бюджет. Таблицы типов и байткод всех подпрограмм верифицируются.

## Основной редактор Qt

В редакторе доступны один документ,
подсветка, открытие/сохранение, проверка, запуск, остановка и строка ввода.
Программы запускаются из несохранённого снимка текста отдельным процессом `abc`.
На этом этапе вывод идёт через обычные каналы процесса; полный протокол из
архитектуры ещё не реализован. Остановка принудительно завершает собственный runner.
Рабочая папка запуска не зависит от расположения временного снимка.

Для Qt нужен комплект разработки Qt 6.8+:

```sh
cmake -S native -B native/build/qt-editor -DABC_BUILD_IDE=ON -DCMAKE_PREFIX_PATH=/path/to/Qt
cmake --build native/build/qt-editor --config Release
ctest --test-dir native/build/qt-editor -C Release --output-on-failure
```

Редактор называется `abc-ide`. Проверка `--smoke-test` запускает несохранённый
пример, передаёт ему число 21 и проверяет вывод 42. Qt дополнительно принимает
`--screenshot /path/to/image.png` вместе с этим режимом. Режим
`--smoke-runtime-error` проверяет двуязычное деление на ноль и строку исходника.
Ошибки содержат заголовок `файл:строка:столбец: КОД`, затем `EN:` и `RU:`.
В редакторе вместо пути временного снимка показывается исходное имя документа.
Синтаксические ошибки и ошибки проверки типов пока могут содержать только английский текст.

## Исторический эксперимент Tcl/Tk

Для Tcl/Tk используется собственный C++ launcher `abc-tk` и скрипт `src/tcl/editor.tcl`.
Python не является зависимостью готового приложения. Launcher обращается к
неизменным публичным функциям C ABI Tcl/Tk 8.6 через непрозрачный `Tcl_Interp`;
структуры интерпретатора и частные функции не используются. См.
[Tcl API](https://www.tcl-lang.org/man/tcl8.6/TclLib/Eval.htm) и
[Tk_Init](https://www.tcl-lang.org/man/tcl8.6/TkLib/Tk_Init.htm).

Параметры CMake для Tcl/Tk: `ABC_BUILD_TK=ON`, `ABC_TCL_LIBRARY`, `ABC_TK_LIBRARY`,
`ABC_TCL_RUNTIME_DIR`. Последний каталог должен содержать `tcl8.6/` и `tk8.6/`.
В Windows дополнительно задаются пути `ABC_TCL_DLL` и `ABC_TK_DLL`.
Скрипты и DLL копируются в дерево сборки и поставку; системная установка Tcl/Tk
после упаковки не требуется. Автоматическое развёртывание Tcl/Tk на Linux/macOS
пока не завершено. Совместимость с Tcl/Tk 9 этим launcher не заявляется.

## Упаковка Qt для Windows

Готовый проверенный пакет этой ветки:
[ABC-Native-Qt-win-x64.zip](dist/ABC-Native-Qt-win-x64.zip).
Распакуйте архив целиком и запустите `Launch.cmd`. В него входят только приложение,
Qt и необходимые библиотеки C++; Python отсутствует.

Из PowerShell в корне репозитория, с установленными средствами сборки MSVC 2022:

```powershell
.\native\scripts\build-windows-qt.ps1 -QtRoot C:\Qt\6.8.3\msvc2022_64
python native/tests/package_smoke.py native/dist --variant Qt
```

Первый шаг собирает и проверяет ядро и Qt, затем создаёт
`native/dist/ABC-Native-Qt-win-x64.zip`. Распакуйте весь архив и откройте `Launch.cmd`.
Python нужен только для проверки пакета разработчиком. Пользователю он не нужен.
Скрипт сравнения двух оболочек сохранён отдельно и для выпуска Qt не требуется.
Пакет проверяется из временной папки с кириллицей и пробелами, без каталогов
Qt, Tcl/Tk и Python в PATH. Проверка распакованных EXE/DLL читает PE-заголовки
и отклоняет CLR-сборки, включая смешанный код; отдельная проверка исключает
хосты Python/.NET/Mono и Python-модули. Контрольная управляемая DLL проверяется
чтением заголовка, без её загрузки или исполнения. Ночная тема проверяется
снимком реального окна.
Linux/macOS заложены в коде; их редакторы и переносимые пакеты ещё требуют проверки.
