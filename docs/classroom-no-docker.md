# Сервер класса abc.pro без Docker

Эта инструкция рассчитана на **Windows-компьютер преподавателя**. Сервер
работает в виртуальном окружении Python, хранит данные в SQLite и проверяет
Pascal-решения локальным компилятором из архива. Ученические компьютеры
подключаются к нему по локальной сети через IP-адрес и порт.

## 1. Подготовьте компьютер

Установите Python 3.10 или новее с командой `py` и среду выполнения .NET 10.
Проверьте установки в PowerShell:

```powershell
py -3 --version
$dotnet = (Get-Command dotnet -ErrorAction SilentlyContinue).Source
if (-not $dotnet) { $dotnet = "$env:USERPROFILE\.dotnet\dotnet.exe" }
& $dotnet --list-runtimes
```

В списке должна быть строка `Microsoft.NETCore.App 10.*`.
На компьютере преподавателя также нужен доступ к Python-пакетам для первой
установки Flask и Waitress. После установки зависимостей для работы сервера
интернет не нужен.

Распакуйте `abc-pro-classroom-local-win-x64.zip` в доступную для записи папку,
например `C:\abc-pro-classroom`. Архив содержит сервер, компилятор и скрипты,
но **не содержит** базы учеников и паролей. Откройте PowerShell в папке,
куда распакован архив. Все команды ниже выполняются из неё.

## 2. Создайте виртуальное окружение и преподавателя

```powershell
py -3 -m venv .abcpro-build\classroom-venv
.\.abcpro-build\classroom-venv\Scripts\python.exe -m pip install -r ClassroomServer\requirements.txt
.\.abcpro-build\classroom-venv\Scripts\python.exe -m ClassroomServer init-admin teacher
```

Последняя команда попросит пароль преподавателя длиной не менее 10 символов.
Учётную запись достаточно создать один раз. Пароль не записывается в команды
и не попадает в серверный архив.

## 3. Запустите сервер

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\start-classroom-server.ps1 -BindHost 0.0.0.0 -Port 8080
```

При следующем запуске используйте ту же команду. Скрипт запускает Python
из `.abcpro-build\classroom-venv`, проверяет наличие компилятора и не
обращается к Docker. Если виртуального окружения ещё нет, он создаст его и
установит зависимости. После изменения `requirements.txt` добавьте `-Setup`.

Для проверки на самом компьютере преподавателя откройте
`http://127.0.0.1:8080/api/health`: ожидается `{"status":"ok"}`. Страница
преподавателя доступна по `http://127.0.0.1:8080/admin`. Войдите созданным
логином и паролем.

Если порт 8080 занят, передайте другой номер через `-Port`, например `-Port
8090`. Адрес `0.0.0.0` заставляет сервер принимать подключения на сетевых
интерфейсах; ученикам этот адрес не сообщайте.

## 4. Создайте задания в браузере

На странице преподавателя нажмите **Управление заданиями**:

1. Создайте группу учеников, например `7-А`.
2. Создайте в ней набор заданий, например `Циклы`.
3. Добавьте ученика и выдайте ему логин и пароль.
4. Создайте задание. Условие и стартовый код можно ввести в форме или
   загрузить UTF-8 файл `.pas`, начинающийся с `{условия}`.
5. Добавьте хотя бы один тест: входные данные и ожидаемый вывод. Открытые
   тесты ученик видит в IDE, закрытые остаются только на сервере.

Набор помогает упорядочить задачи в группе. Список ученических задач и
статусы решений отображаются на главной странице преподавателя. Итоговые
статусы появляются после повторной проверки решения на сервере.

## 5. Подключите ученические компьютеры

На компьютере преподавателя выполните `ipconfig` и найдите его IPv4-адрес в
локальной сети, например `192.168.1.20`. Разрешите входящие TCP-соединения на
выбранный порт в брандмауэре Windows **для частной сети**. С компьютера
ученика проверьте `http://192.168.1.20:8080/api/health`.

Передайте ученику IPv4-адрес, порт, его логин и пароль. В abc.pro он выбирает
**Класс → Войти на сервер…**, вводит эти данные и скачивает задания через
**Класс → Скачать задания…**. Преподаватель видит подключения и результаты
на странице `/admin`.

Не открывайте этот порт в интернет. По обычному HTTP пароль передаётся по
локальной сети без шифрования; для общей или недоверенной сети настройте
HTTPS-прокси.

## Данные, обновление и ограничения

База SQLite, учётные записи, тесты и ключ сессии хранятся в
`ClassroomServer\data`. Перед переносом или обновлением остановите сервер и
сохраните копию **всей этой папки**. При обновлении распакуйте новую версию
архива поверх программы, сохранив `ClassroomServer\data`, затем запустите
скрипт с `-Setup`, если изменились Python-зависимости. Старые задания
сохраняются, а новые поля базы добавляются при запуске.

Локальная проверка выполняет ученический код с правами учётной записи,
запустившей сервер. Виртуальное окружение Python не изолирует доступ к
файлам и сети. Лимиты времени и объёма вывода помогают при ошибочных
программах, но не превращают такой запуск в безопасную песочницу. Используйте
отдельную учётную запись Windows без административных прав и личных данных.
Для выполнения недоверенного кода с контейнерной изоляцией предусмотрен
[необязательный режим Docker](classroom.md#необязательный-режим-docker).

## Сборка архива из исходников

Если вы разрабатываете проект из репозитория, после сборки portable-пакета
создайте серверный архив:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\build-portable.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\build-classroom-server.ps1
```

Результат: `Release-classroom\abc-pro-classroom-local-win-x64.zip`. Проверка
реального компилятора и веб-сервера запускается так:

```powershell
.\.abcpro-build\classroom-venv\Scripts\python.exe -m unittest tests.test_classroom_server -v
```
