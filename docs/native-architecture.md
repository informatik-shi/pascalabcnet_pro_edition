# Архитектура переносимого PascalABC на C++

Дата: 29 октября 2026 года. Статус: архитектура и развивающийся сквозной прототип.

Новая реализация объединяет редактор и интерпретатор в переносимое приложение для Windows 10/11, Linux и macOS. Первый релиз исполняет согласованный набор конструкций PascalABC.NET. SPython подключается следующим языковым модулем к тому же ядру. Рабочее название новой реализации — ABC Native.

Основное решение: C++20, собственный анализатор типов и интерпретатор типизированного байткода. После сравнения выбран Qt Widgets. Ночная тема включается по умолчанию; ошибки исполнения одновременно показываются на английском и русском. Tcl/Tk сохранён как экспериментальный прототип для истории сравнения. Пользователь распаковывает пакет своей ОС и запускает приложение; .NET, Mono, Python и установленный компилятор C++ для выполнения программ не нужны.

Под требованием «все типы данных должны быть известны» принимается статическая типизация: до запуска известны типы выражений, переменных, элементов коллекций, параметров и результатов функций. Тип можно вывести из исходного кода. Это не требует указывать его вручную в каждом объявлении.

## Границы совместимости

Перенос языка и перенос всей экосистемы .NET — разные объёмы работ. Существующая реализация использует генерацию .NET-кода и библиотеки .NET; например, `bin/Lib/PABCSystem.pas` импортирует `System`, `System.IO` и коллекции .NET. Такие зависимости необходимо заменять собственными модулями.

Первый релиз обозначаем **0.1 с поддержкой базового профиля PascalABC.NET**. Полная совместимость с PascalABC.NET не заявляется. Исходные `.pas` поддерживаются в пределах опубликованной матрицы конструкций и библиотек. Существующие `.pcu`, .NET DLL и EXE не являются входным форматом новой машины.

В репозитории сохраняются обе реализации: существующая служит эталоном поведения, новая развивается в `native/`. Переключение существующего редактора и изменение текущих сборок в этот этап не входят. Уже реализован сквозной прототип с базовыми числовыми типами, char/word и строками, динамическими массивами, записями, пользовательскими подпрограммами, условиями, циклами `while/for/repeat`, `foreach` по строкам, массивам и `List<T>`, `break/continue`, вводом/выводом и редактором Qt. Перенесён первый набор `PABCSystem`: математика, строки, операции массивов, начальный `List<T>` и текстовые файлы с нативными кодировками. Типы элементов, полей, параметров и результатов определяются до запуска. VM использует отдельные кадры вызовов, копирование записей по значению и ссылки для массивов/списков; верификатор проверяет таблицы типов и все тела подпрограмм. Прогресс по 100 исходным модулям поставки записан в `native/stdlib-status.json`. Полный профиль 0.1 ещё не реализован; актуальный состав и ограничения описаны в `native/README.md`.

## Технологии и платформы

VM имеет единый enter_routine и повторно входимый run_to(depth). Нативные
провайдеры вызывают типизированные пользовательские функции через Values.invoke,
используя те же globals, стек, сервисы, счётчик инструкций и лимит кадров.
Внешнее положение стека восстанавливается после callback, SourceLocation —
через RAII; ошибки сохраняют позицию внутренней инструкции. Select/Where хранят
проверенный индекс функции и независимый курсор. Метаданные включают входной
sequence of T, результат sequence of U и сигнатуру функции; неизвестных типов
в момент вызова нет. Лямбды и полноценные значения делегатов остаются в плане.

SelectMany использует тот же callback-провайдер с отдельным внутренним курсором
и индексом. Возвращённые массивы/List/строки адаптируются к проверенному
sequence of U; следующий внешний элемент не запрашивается до завершения
внутреннего. Верификатор выводит U из результата функции и проверяет его
совпадение с элементом выходного sequence.

Params хранится в формальной сигнатуре и проверяется до запуска. Анализатор
различает прямую передачу точно совпадающего массива/nil и упаковку хвоста
в типизированный array_literal. VM получает обычный фиксированный набор
параметров; упаковка и преобразования не выполняются динамически при вызове.
Верификатор требует последний одномерный массив по значению.

Const отмечается в синтаксической сигнатуре и анализе изменяемых мест хранения;
передача по значению остаётся обычной. Запрещаются присваивание, var/out и
итерационные записи через const-параметр. Out нормализуется в существующий
var-режим по исходному компилятору, без отдельной операции VM и обнуления.

Предикатные запросы передают в отдельную типизированную операцию индекс
T -> boolean и вид запроса. Нативный обход вызывает общий движок VM, реализует
ранний возврат, проверку полного завершения и отдельные ошибки совпадений.
Sum/Average с selector сводятся в HIR к Select и числовому агрегату; результат
selector допускается только integer/int64/real.

Reverse использует общий буферизованный провайдер среза; DefaultIfEmpty —
тот же курсор и отдельную типизированную ячейку запасного значения. Для него
есть отдельная операция байткода с аргументом T вместо integer. SequenceEqual
потребляет два курсора синхронно и возвращает boolean; верификатор требует
одинаковый sequence of T у обоих операндов. AsEnumerable не создаёт новый
провайдер поверх уже существующей последовательности.

Строковое представление sequence of char хранит общий неизменяемый захват
UTF-16 в типизированной ячейке, длину и независимый индекс курсора. Байткод
sequence_wrap разрешает string только для результата sequence of char.
Суррогатные единицы сохраняются; nil остаётся типизированным nil. Точная
ссылочная идентичность отдельных строковых преобразований пока не реализована.

Concat хранит два типизированных источника, отдельный индекс текущего источника
и общий индекс курсора. Второй курсор открывается после завершения первого;
повторные обходы независимы. Операторы добавления элемента сводятся к Concat
с одноэлементным захватом. Верификатор требует два одинаковых sequence of T
на стеке, а глубина композиции учитывает обе ветви.

Необязательные параметры имеют известные типы. Каждый default-аргумент
компилируется в скрытую типизированную подпрограмму; недостающие аргументы
вызывают её слева направо. Это сохраняет повторное вычисление, ошибки и общий
лимит рекурсии, не разворачивая рекурсивные выражения в дереве анализатора.
Сигнатуры регистрируются до анализа инициализаторов глобальных переменных.
Прямые ссылки на переменные/параметры в default-выражении запрещены по исходному
convert_strong_to_constant_node; вызовы функций разрешены. default(T) передаётся
в верифицируемую операцию make_default с отдельным режимом обнуления ссылок.


Конструкторы `Seq` и `SeqFill` возвращают известный до запуска `sequence of T`.
Seq сразу копирует params-массив; SeqFill хранит одно захваченное значение и
выдаёт копии записей при переборе. Двухаргументный Range для integer/char хранит
начало и размер с включёнными границами. Провайдеры используют общий обход,
запросы и материализацию; большие повторы и допустимые диапазоны можно начать
перебирать без выделения массива. При этом лимиты копирования, выдачи и типов
сохраняются. Range с целым шагом для integer/char хранит 64-битный размер,
начало и шаг; параметры проверяются статически. Общее продолжение генератора
sequence_resume используется foreach, запросами, материализацией и MinMax.
Оно откладывает ошибку нулевого шага до начала перебора и проверяет завершающее
сложение после последней выдачи. Короткие запросы и break это сложение не
выполняют. BigInteger-диапазоны с двумя/тремя аргументами используют отдельный курсор
с неизвестной заранее длиной. Хранятся три неизменяемых BigInteger-значения;
продолжение выполняет ограниченное сложение и сравнение без вычисления разности
границ. Шаг и граница захватываются по значению, при начале обхода создаётся
независимый курсор. Все потребители используют продолжение до false вместо
обязательного предварительного размера. Лимиты работы, памяти и 65536 бит
применяются также к завершающему шагу. PartitionPoints/Linspace используют отдельный курсор накопления real-шага:
валидация n и вычисление h откладываются до начала обхода, затем r увеличивается
после каждой выдачи. Накопленная погрешность сохраняется, прижимания к конечной
точке нет. Вычитание n-1 у Linspace выполняется при вызове с проверкой переполнения.
Профиль real остаётся конечным; NaN/Infinity исходной .NET среды не поддерживаются.
Real Range использует отдельный нативный планировщик Decimal96: signed 96-bit
коэффициент, масштаб 0..28, округление к ближайшему чётному. Double-преобразование
адаптировано из .NET 10 Decimal.DecCalc (MIT); арифметика выполняется через
ограниченные BigInteger-промежуточные значения без .NET. План строится при первом
продолжении, использует временную квоту 256 ячеек и собственный счётчик работы.
Точки вычисляются a+i*step с раздельными умножением и сложением; конечная граница
прижимается по исходному относительному допуску 1e-14. Равные границы и неверное
направление обрабатываются до decimal-преобразования. Decimal overflow, division
by zero и integer-count overflow двуязычны; пользовательский decimal и NaN/Infinity
пока отсутствуют.

Числовые Sum/Average/Product используют типизированную редукцию без материализации.
Метаданные определяют тип результата: Product(integer) возвращает int64, Average —
real. Проверяются промежуточные переполнения и завершение исходного генератора.
Пустой Average(BigInteger) сохраняет исходный ноль, остальные числовые Average
сообщают E_EMPTY. PartialSum(integer/real/BigInteger) — композиционный провайдер:
исходный курсор открывается при первом продолжении, накопитель принадлежит одному
обходу, сохранённые BigInteger-значения неизменяемы. Размер не объявляется известным,
чтобы Count не пропускал арифметику. Глубина цепочек ограничена call_limit при создании
и продолжении: это ограничивает рекурсию обхода и освобождения shared_ptr-цепочек.

Take/Skip/TakeLast/SkipLast — провайдер среза с тем же типом элемента T.
Курсоры открывают источник только по необходимости; Take останавливается перед
следующим MoveNext после count выдач. TakeLast буферизует хвост до конца источника,
SkipLast выдаёт с упреждением count+1. Ячейки ограниченного буфера переиспользуются,
записи копируются на выдаче, ссылки сохраняют идентичность. Профиль nil различается
по исходным реализациям: Take/Skip проверяют при вызове; TakeLast/SkipLast откладывают
открытие, а TakeLast(count<=0) вовсе не открывает источник. Общий sequence_guard
ограничивает создание и рекурсию всех композиционных провайдеров.

Общий механизм последовательностей также исполняет `Any`, `First`/`Last`,
`FirstOrDefault`/`LastOrDefault`, `ElementAt`/`ElementAtOrDefault` и `Contains`.
`Single`/`SingleOrDefault` проверяют единственность и сообщают о втором элементе
двуязычным E_MANY, прекращая дальнейший обход генератора.
Сигнатуры и тип результата T либо boolean проверяются до запуска, включая
метаданные байткода. Индексируемые источники используют прямой доступ; генераторы
сохраняют выдачу предшествующих значений и короткое завершение с общими лимитами.
Перегрузки с предикатами и общий механизм делегатов остаются отдельным этапом.

Для `School.SwapSubstr` добавлен статический 16-битный движок PCRE2 10.49 на C.
Его контексты не становятся динамическими типами языка: HIR и verifier требуют
ссылку на строку и две строки до запуска. Исполнение ограничивает работу,
память и результат; ошибки одновременно имеют русский и английский текст.
Сохраняются проверки присутствия ключей, последовательность пустых совпадений
и единственная запись результата исходного School. Это явно ограниченный
профиль регулярных выражений. На том же движке реализованы статически типизированные
`PABCSystem.IsMatch`, `MatchValue`, их строковые формы и `Regex.IsMatch` с настройками
по умолчанию; полный API и синтаксис .NET Regex остаются в плане.

| Область | Решение | Причина |
| --- | --- | --- |
| Ядро языка | C++20 без Qt | Независимые CLI, тесты и повторное использование |
| Пользовательский интерфейс | Qt 6.8+ Widgets, ночная тема | Выбран после сравнения с Tcl/Tk |

C применяется на границах внешних модулей, если они понадобятся; писать одно и то же ядро одновременно на C и C++ не требуется. LLVM, JIT и преобразование Pascal в C++ в первую версию не входят: запуск программы не должен требовать внешнего инструментария.

Подтверждённые пользователем семейства ОС: Windows 10/11, Linux и macOS. Предлагаемые цели проверки: Windows x64, Linux x64, macOS arm64 и x64. Точные минимальные версии Linux/macOS фиксируются вместе с выбранной версией Qt в этапе M0. Ориентир Linux — Ubuntu 22.04 и 24.04 с X11 и Wayland; совместимость подтверждается готовым пакетом на каждой системе.

Qt 6.8 показывает осуществимость выбранной платформенной матрицы: Windows 10 1809+, Windows 11, Linux, macOS 12+ на x64/arm64. Это справочная точка, а не зафиксированная зависимость: для сборки выбираем доступную поддерживаемую версию Qt, сохраняющую целевые ОС, и закрепляем точный выпуск и контрольные суммы. См. [официальную матрицу Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html) и [матрицу актуальной ветки](https://doc.qt.io/qt-6/supported-platforms.html).

## Состав приложения

```text
abc-ide                         abc check / abc run
  |                                  |
  +------ compiler API --------------+
               |
      Pascal frontend       SPython frontend после 0.1
               |                    |
               +------ typed HIR ---+
                            |
                    проверка инвариантов
                            |
                    типизированный байткод
                            |
                      верификатор
                            |
                       VM и runtime
```

| Модуль | Ответственность | Зависимости |
| --- | --- | --- |
| `source` | Файлы, версии текста, диапазоны исходника, диагностика | Стандартная библиотека C++ |
| `types` | Реестр типов, сигнатуры, правила преобразований | `source` |
| `pascal` | Лексер, синтаксическое дерево, области видимости, правила Pascal | `source`, `types`, `hir` |
| `hir` | Общее типизированное промежуточное представление | `source`, `types` |
| `bytecode` | Генерация, формат модуля, верификация | `hir`, `types` |
| `vm` | Инструкции, кадры вызова, остановка, отладочные события | `bytecode`, `runtime` |
| `runtime` | Управляемые объекты, строки, массивы, ввод и вывод | Типы и абстракции платформы |
| `stdlib` | Стандартные функции и Pascal-модули | `runtime`, реестр сигнатур |
| `compiler` | Общий конвейер анализа и построения программы | Frontend, HIR, bytecode |
| `language-service` | Ошибки, тип под курсором, завершение имён | `compiler` |
| `ide` | Документы, окна, команды запуска, панели | Qt, `language-service`, протокол runner |
| `runner` | CLI, выполнение и протокол с IDE | `compiler`, `vm` |

Ядро не зависит от GUI. VM не знает о синтаксисе Pascal и SPython. Frontend сохраняет специфичные правила языка, а затем выражает их через общие типизированные операции. Варианты языка передаются через контекст анализа; изменяемых глобальных переключателей между языками нет.

## Конвейер обработки программы

1. `SourceManager` создаёт снимок всех исходников с идентификаторами файлов и версиями. Несохранённый текст редактора является полноценным исходником.
2. Лексер и парсер Pascal строят AST с диапазонами исходного текста. Предлагаемая реализация — рекурсивный спуск для объявлений и операторов, Pratt parser для выражений. Существующая грамматика служит спецификацией для сверки, а не автоматически переносимым C#-кодом.
3. Разрешение имён строит области видимости, символы модулей и сигнатуры функций. Затем анализируются тела, перегрузки и вывод типов.
4. Семантический анализ выдаёт typed HIR. Каждый узел выражения имеет конкретный `TypeId`; преобразования типов представлены отдельными узлами.
5. Проверка HIR запрещает оставшиеся неизвестные типы, неразрешённые символы и неподдерживаемые конструкции. Ошибочная программа не передаётся на выполнение.
6. Генератор создаёт байткод, таблицы типов, констант и соответствия исходнику. Верификатор проверяет операнды, переходы, вызовы и состояние стека.
7. VM выполняет проверенную программу через собственную стандартную библиотеку.

`check` выполняет анализ без пользовательских побочных эффектов. Даже если ошибка находится в недостижимой ветке, она должна быть выявлена до запуска. IDE может показывать частичный результат анализа незавершённого текста, но не исполняет его.

Текущий верификатор сначала проверяет метаданные всех инструкций, включая недостижимые. Анализ стека сохраняет состояния в точках входа переходов; прямые участки проходят с одним текущим стеком. Типы и высота на слияниях и обратных переходах должны совпадать. Такой обход сохраняет лимиты стека и суммарного размера состояний, но не копирует растущий стек на каждой инструкции длинного выражения. Типы ссылок, контейнеров и общих объектов стандартных модулей проверяются явно; например, все обращения к общему кэшу School используют один тип List<integer>.

## Система типов

### Статические гарантии

- Каждая переменная, поле, параметр, результат и выражение имеет тип до старта VM.
- `var x := 10` разрешён: анализатор выводит `integer`. Присваивание `x := 'text'` выдаёт ошибку.
- Тип массива включает тип элемента и форму массива. Границы статического массива входят в описание типа; длина динамического массива определяется во время работы.
- Тип функции включает параметры, способы передачи и результат. `var` и `out` требуют подходящего изменяемого места хранения, а не произвольного выражения.
- Перегрузки и допустимые преобразования разрешаются до генерации байткода. Переходы между знаковыми и беззнаковыми числами задаются таблицей правил, а не приведениями C++.
- `Unknown`, `TypeVariable` и `ErrorType` существуют только в анализаторе. Выход анализатора с ошибками не является исполнимым модулем.
- `nil` проверяется по контексту допустимого ссылочного типа. Сам по себе `nil` не даёт достаточно данных для вывода типа переменной.
- Разрешённые в будущем `object`, интерфейсы и базовые классы будут известными статическими типами. Конкретный подтип объекта может определяться при выполнении; это не превращает значение в неизвестный тип.

```pascal
begin
  var n := 10;                  // integer
  var x: real := n / 2;         // real
  var a: array of integer;
  // n := 'text';               // ошибка до запуска
end.
```

### Внутреннее описание типов

В текущем прототипе базовые типы заданы перечислением `Type`; реестр составных описаний ниже является следующим этапом. Байткод пока хранится в памяти, загрузка внешних модулей и кэш ещё не реализованы.

`TypeRegistry` интернирует неизменяемые `TypeDescriptor`: вид, параметры, поля, сигнатуры, размер и выравнивание внутри VM, а также сведения о ссылках для сборщика мусора. Именованные типы сохраняют свою идентичность; структурное совпадение не даёт автоматической совместимости.

`TypeId` — индекс в пределах конкретной сессии анализа/модуля. При загрузке модуля его таблица типов связывается с реестром VM. Числовые индексы не считаются глобальными идентификаторами между запусками и процессами.

Числа используют фиксированные разрядности; Pascal `integer` не зависит от размеров C++ `int`, `long` и указателя. `uint64` никогда не хранится через `double`. Переполнение, деление на ноль, минимальное целое при делении на `-1`, сдвиги и сужение реализуются явно, без неопределённого поведения C++.

Для 0.1 предлагается профиль с проверяемым целочисленным переполнением. Если поведение эталона отличается, это отражается в матрице совместимости; режим совместимости вводится отдельно и тестируется. Исходные директивы не игнорируются молча.

Текст исходников и сообщения протокола — UTF-8, значения Pascal `string` — UTF-16. Позиции исходника хранятся как байтовые диапазоны с преобразованием для Qt. Это позволяет сохранить Pascal-операции со строками и одинаковую диагностику на всех ОС. Unicode-таблицы сравнения имён фиксируются; правила регистронезависимого поиска не зависят от системной локали. DefaultEncoding изначально CP1251; BOM распознаётся автоматически, явная Encoding задаёт другую кодировку.

## Исполнение и память

В текущем прототипе строки хранятся через `std::u16string`, массивы и списки — через ссылочные `Aggregate`, записи копируются по значению. Общей пользовательской объектной модели и циклического GC ещё нет. Управляемая куча ниже описывает целевую модель для расширения профиля 0.1.

Встроенные Addr32/CalcIP имеют отдельные типы с проверяемыми приватными полями и сигнатурами операций. `sequence of T` хранит известный до запуска тип элемента; источник и состояние отдельного перебора разделены. Каждый `foreach` создаёт собственный курсор с int64-счётчиком. Общий код в `native/src/sequences.cpp` управляет представлениями массивов/List, версиями списков, копированием записей, Count/ToArray и ограничениями ресурсов; IP-провайдер в `school_ip.cpp` определяет свои границы и выдачу элементов. Последовательность удерживает источник после возврата из создавшей её функции. Эти встроенные источники не требуют загрузки .NET-типов или Python.

Преобразование массива/List в последовательность допускается только при точном совпадении T. Оно сохраняет ссылку на контейнер, включая nil; изменение списка проверяется при каждом продолжении и завершении перебора. ToArray выполняет явное копирование элементов с обычными правилами значений и ссылок. Полный пользовательский yield и остальные операции LINQ пока не реализованы; лямбды и захваты поддерживаются в текущем профиле.

VM использует стек операндов, кадры вызовов и отдельную управляемую кучу. Арифметические инструкции различают типы: `ADD_I32`, `ADD_U64`, `ADD_F64`; обращения к массивам содержат сведения о типе элемента. Слот может быть общим контейнером хранения, но тип допустимого значения задаётся проверенным кодом. Это не динамическая типизация языка.

Верификатор проверяет совпадение типов и высоты стека на всех слияниях потока управления, сигнатуры вызовов, допустимость возвратов, индексы таблиц и границы переходов. VM дополнительно проверяет индексы массивов, `nil`, диапазоны, доступ к полям и лимиты ресурсов. Формат байткода имеет версию; при несовпадении версия отклоняется, а кэш перестраивается из исходников.

Куча использует точный неперемещающий mark-and-sweep GC: корни — глобальные переменные, кадры, стек операндов и временно закреплённые значения встроенных функций. Дескрипторы типов позволяют обходить ссылки внутри массивов и записей. Сборка выполняется в безопасных точках; циклы ссылок не требуют особого поведения пользователя. Типы языка не реализуются напрямую через произвольные C++-объекты пользователя.

Ссылки на элементы для `var`/`out` представлены проверяемым местом хранения: владелец и путь/индекс. Удержание ссылки сохраняет владельца живым; изменение размера массива не оставляет висячий C++-указатель. Файлы принадлежат контексту исполнения и закрываются при явном закрытии, завершении или остановке программы; GC не определяет момент освобождения системного ресурса.

Для остановки VM проверяет отмену между инструкциями; длительные встроенные операции обязаны иметь точки отмены или ограниченный объём работы. Контекст задаёт лимиты стека, управляемой памяти и вывода. Эти лимиты и отдельный процесс обеспечивают управляемый запуск, но не являются полной ОС-песочницей для недоверенного кода.

Отладочная таблица связывает инструкции с исходником и локальными переменными. Она закладывается сразу; остановка на точке, шаг и просмотр значений реализуются после базового запуска. Оптимизации, нарушающие понятное пошаговое выполнение, в первом релизе отключены.

## Редактор и процесс выполнения

Первый редактор содержит вкладки `.pas`, номера строк, подсветку синтаксиса, отступы, поиск, переход к ошибке, проверку программы, запуск и остановку. Ввод и вывод показываются в отдельной панели. Завершение локальных имён и просмотр типа используют тот же анализатор, что и команда запуска.

Анализ редактора выполняется в фоновом задании по неизменяемому снимку текста. Устаревший результат отбрасывается по версии документа; закрытие документа отменяет его задания. Изменять Qt-виджеты может только поток интерфейса. На первом этапе допустим полный повторный анализ файла с задержкой после ввода; инкрементальность добавляется по измерениям.

Пользовательская программа запускается в **отдельном процессе `abc-runner`**. IDE передаёт снимки исходников, выбранный файл входа, рабочую папку и настройки исполнения. Runner заново проверяет программу общим compiler API и запускает VM. Ошибка, зависание или авария runner не закрывают редактор. Сначала отправляется запрос остановки; после ограниченного ожидания IDE завершает процесс.

Для связи используется версионированный протокол поверх каналов процесса: кадр с длиной и JSON в UTF-8. События: готовность, диагностика, вывод, запрос ввода, завершение; команды: запуск, порция ввода, конец ввода, остановка. Пользовательский `writeln` превращается в событие вывода и не смешивается с управляющими кадрами. Вывод обрабатывается порциями с ограничением очереди. Некорректные и слишком большие кадры отклоняются.

В обычном CLI-режиме `abc run file.pas` stdin/stdout остаются обычной консолью; протокол включается отдельным режимом для IDE. `abc check file.pas` возвращает код результата и диагностику, при необходимости в JSON. Точки расширения для LSP и DAP сохраняются, но отдельные серверы этих протоколов для 0.1 не требуются.

## Подключение SPython

Обязательное ограничение новой поставки: Python runtime и готовые Python-модули
в неё не входят. Запрещены CPython/libpython, мосты к CPython, `.py/.pyc/.pyd`
и вызов внешнего Python. Нужные возможности модулей реализуются на C++ и
подключаются через типизированные сигнатуры общего ядра. Это относится также
к возможностям NumPy, pandas и Matplotlib: массивы и вычисления, таблицы и
построение графиков потребуют собственных реализаций, графика использует Qt.
До переноса конкретная возможность выдаёт явную ошибку о неподдерживаемой функции.
Автоматического перехода на установленный у пользователя Python нет.
Служебные проверки разработчика на Python не входят в приложение и не являются
обязательной зависимостью сборки CMake или упаковки Qt.

SPython получает собственные lexer/parser, AST, разрешение имён и правила вывода типов. Его frontend выдаёт тот же typed HIR. В существующем коде `AdditionalLanguages/SPython/SPythonLanguageInfo/SPythonLanguage.cs` уже видны различия: регистр имён, нулевая индексация строк и отдельные правила семантики. Их нельзя заменять единственным глобальным режимом Pascal.

Общее ядро предоставляет операции со строками, массивами, объектами и вызовами; frontend выбирает конкретные операции и правила индексации. Совместное ядро не означает, что синтаксически похожие деление, остаток, диапазоны или циклы двух языков имеют одинаковую семантику.

В будущем SPython также статически типизирован. Неоднозначные пустые коллекции и функции требуют контекста или аннотации. Разнородные значения допускаются только через явно определённый общий тип или поддерживаемый составной тип; скрытого `any` нет. Совместимость с текущим SPython проверяется собственными тестами; совместимость со всем CPython и его бинарными пакетами не заявляется.

## Переносимая поставка

«Без установки» означает отдельный готовый пакет для каждой ОС и архитектуры. Один исполнимый файл на все ОС не создаётся. Все необходимые сторонние библиотеки приложения входят в пакет; системный загрузчик, графическая среда и совместимая libc остаются требованиями ОС.

| Платформа | Пакет | Условия проверки |
| --- | --- | --- |
| Windows | ZIP с EXE, Qt DLL, плагинами и необходимыми runtime DLL | Запуск обычным пользователем без Qt, .NET и Visual C++ SDK |
| Linux | tar.gz с исполнимыми файлами, библиотеками, Qt-плагинами и launcher | Сборка на выбранной базовой системе, проверка glibc, X11 и Wayland |
| macOS | ZIP с `.app` и встроенными frameworks, CLI внутри bundle | Подпись и notarization для публичного пакета; проверка arm64 и x64 |

Основной Linux-пакет — извлекаемый каталог. AppImage можно добавить после него как удобную оболочку; отсутствие FUSE не должно блокировать базовый запуск.

При наличии `portable.json` рядом с поставкой настройки, журнал и история сохраняются в указанной относительной папке `data/`. Если она недоступна для записи, приложение сообщает об этом и предлагает выбрать другую папку. В обычном режиме используются стандартные пользовательские каталоги ОС. Изменять подписанный macOS bundle для хранения данных не требуется: переносимая папка данных располагается рядом с `.app`.

Все ресурсы ищутся относительно исполнимого файла/bundle, а не текущей рабочей папки. Для программ рабочая папка задаётся отдельно, по умолчанию рядом с главным исходником. Автообновление, регистрация ассоциаций и запись в системный реестр не требуются для первого запуска.

Состав Qt-библиотек и плагинов собирается по [официальной схеме развёртывания Qt](https://doc.qt.io/qt-6/deployment.html) и проверяется в чистой системе. Сборка фиксирует версии и происхождение зависимостей. Сохраняются лицензии и уведомления исходного проекта из `doc/license.txt`; для распространяемых компонентов ведётся список лицензий. Qt предлагается подключать динамически; окончательный состав поставки проверяется по условиям выбранных модулей, см. [условия Qt LGPL](https://doc.qt.io/qt-6/lgpl.html).

## Структура новой реализации

```text
native/
  CMakeLists.txt
  CMakePresets.json
  include/abc/                 публичные интерфейсы ядра
  src/
    source/ types/ hir/
    frontends/pascal/
    bytecode/ vm/ runtime/
    compiler/ language_service/
    cli/ runner/ ide/
  stdlib/pascal/               исходные переносимые модули
  tests/
    lexer/ parser/ types/ vm/
    compatibility/ packaging/

  packaging/linux/
  packaging/macos/
```

Это целевая структура каталогов. В текущем небольшом прототипе модули представлены отдельными файлами в `native/src/`, а альтернативный интерфейс Tcl/Tk находится в `native/src/tcl/`. SPython добавляется в `src/frontends/spython/` после первого релиза. Кэш модулей хранится в пользовательских данных; ключ включает хеш исходников и зависимостей, версию компилятора, профиль языка, формат байткода и версию стандартной библиотеки. Удаление кэша не лишает пользователя возможности запустить программу из исходника.

## Порядок реализации

| Этап | Результат | Критерий готовности |
| --- | --- | --- |
| M0 | Каркас CMake, закреплённые зависимости, матрица совместимости и семантики | Ядро и пустое окно собираются на трёх ОС; для спорных правил есть эталонные примеры |
| M1 | Типы, исходники, диагностика, lexer/parser, CLI `check` | Арифметика и объявления получают правильные типы; ошибочные присваивания отклоняются |
| M2 | Typed HIR, байткод, verifier, VM, консольный ввод и вывод | Полный путь от `.pas` до результата работает без .NET |
| M3 | Функции, рекурсия, массивы, строки, записи, множества, GC и модули | Каталог типов 0.1 и базовая библиотека проходят выбранные тесты |
| M4 | Редактор, анализ в фоне, runner и протокол | Несохранённая программа запускается; остановка цикла и авария runner сохраняют рабочий IDE |
| M5 | Пакеты и выпуск 0.1 | Пакеты проходят проверку в чистых системах без установленного инструментария |

Первый сквозной пример для M2: ввод целого числа, типизированное вычисление в цикле и вывод результата. Ему сопутствуют отрицательные примеры: смешение строки и числа, неизвестное имя, выход за границы и деление на ноль. Пользователь видит ошибку исходника, а не сообщение C++.

Календарные сроки определяются после M0: перенос всех возможностей PascalABC.NET существенно шире первого профиля. Расширение профиля оформляется изменением матрицы и соответствующими тестами.

## Проверка совместимости и выпуска

Эталон — существующий PascalABC.NET этого репозитория. Из `TestSuite` отбираются небольшие самодостаточные программы по каждой заявленной возможности. Тесты помечаются как поддерживаемые, ожидаемо неподдерживаемые или расходящиеся с эталоном. Набор сопоставления хранит версию эталона, исходник, вход, ожидаемые значения/вывод и согласованные отличия. Нормализация допустима для переводов строк и платформенных путей, но не для скрытия числовых или строковых ошибок.

Обязательные проверки включают границы всех целых разрядностей и точность `uint64` выше 2^53, смешанные числовые выражения, UTF-16 и кириллицу, индексы строк/массивов, копирование записей, передачу `var`/`out`, рекурсию, корни GC и циклы ссылок. Неизвестный или неподдерживаемый тип не должен попасть в исполнимый HIR.

Генерируемые повреждённые модули проверяют отказ verifier без аварии; fuzzing применяется к parser, decoder и протоколу. AddressSanitizer и UndefinedBehaviorSanitizer запускаются там, где их поддерживает выбранный инструментарий. GUI-проверки охватывают ввод, остановку, устаревшие диагностики и ограничение вывода.

Приёмка переносимости выполняется на чистых целевых ОС: путь с пробелами и кириллицей, запуск не из папки приложения, отсутствие прав администратора, перенос каталога, read-only-поставка, сохранение данных и запуск без сети. Отсутствие зависимостей от .NET, Mono и Python подтверждается этими запусками. Размер поставки, скорость старта и выполнения измеряются на M2 и M5; обещания равной скорости с существующим JIT до измерений не даются.

## Основания в существующем репозитории

- `README.md` и `docs/build-portable-spython.md` описывают текущую поставку и зависимости .NET/Python.
- `Parsers/PascalABCParserNewSaushkin/ABCPascal.y` содержит действующую грамматику Pascal и показывает объём расширений языка.
- `TreeConverter`, `SemanticTree`, `SyntaxTree` и `NETGenerator` разделяют анализ и генерацию существующего компилятора.
- `AdditionalLanguages/SPython/SPythonParserKrylovMovchan/SPythonParser.y` и `SPythonLanguage.cs` задают отдельный синтаксис и семантические настройки SPython.
- `bin/Lib/PABCSystem.pas` показывает стандартные типы, строковые настройки и зависимости стандартного модуля от .NET.
- `TestSuite` и `TestSuiteAdditionalLanguages` предоставляют исходные примеры для формирования наборов совместимости.

Переносится поведение, подтверждённое этими материалами и тестами. Бинарные зависимости старого приложения в новую переносимую поставку не включаются автоматически.

Инициализаторы `new T[n](...)` и `new T[rows,cols]((...),(...))` проходят проверку постоянных размеров и типов в анализаторе. Генератор выделяет типизированный временный массив, затем записывает элементы по порядку через существующие проверяемые инструкции. Отдельные проверки покрывают копирование записей, общие ссылочные поля, рекурсию и ошибки до вызовов инициализаторов. Исходный `TestSuite/params5.pas` выполняется нативным runner без изменения файла.

Скалярные const связываются до исполнения. Изолированный вычислитель допускает только литералы, чистые операторы и базовые преобразования; он генерирует обычный проверяемый байт-код и использует ту же VM. Ссылки на переменные и пользовательские вызовы в него не попадают. Библиотечные инициализаторы констант сохраняются в отдельной начальной секции и выполняются один раз; локальные константы также имеют статическое хранилище. Запись и var/out для const отклоняются анализатором. Исходные const1 и const3 исполняются в нативном CTest.

Резервное чтение real для libc++ использует отдельную C-локаль и strtod_l с явной проверкой десятичной грамматики. Ненулевые субнормальные значения принимаются; переполнение и округление ненулевого литерала к нулю отклоняются. Сохранён отдельный тест этого пути, даже когда стандартная библиотека предоставляет floating from_chars.

Zip хранит типизированные источники и необязательный идентификатор функции, создаёт независимые курсоры для каждого обхода и открывает все источники перед продвижением. Верификатор проверяет число источников, точные типы аргументов, передачу по значению и тип кортежа либо результата функции. Продвижение слева направо, отложенный nil и снимок Current списка покрыты проверками с побочными эффектами. Ни делегат .NET, ни внешний интерпретатор для этого не используются; лямбды используют общий механизм типизированных вызовов и захваченных ячеек.

TakeWhile/SkipWhile используют общий типизированный механизм преобразований последовательностей. Вид операции представлен enum, сигнатура предиката проверяется при анализе и верификации. Каждый курсор сохраняет отдельное состояние начального пропуска; проверка индекса действует и после его завершения. Граничный тест с подготовленным курсором отличает индексированную перегрузку от обычной при переходе через MaxInt без миллиардов итераций.

Встроенная локализация ошибок компилятора добавляет 270 подробных русских сообщений и шаблоны с именами и типами. Error сохраняет исходный английский текст, код и SourceLocation; явно заданный русский текст имеет приоритет. Для ещё неизвестных внутренних инвариантов используется русская категория, английская подробность сохраняется. Ошибки параметров CLI и чтения исходника используют общий EN/RU формат и код возврата 2. Тесты проверяют кириллические идентификаторы, позиции, типы, перегрузки и запуск CLI; захват CLI в CMake явно декодируется как UTF-8.

Именованные процедурные значения представлены отдельным видом составного типа callable: статический результат и список точных типов/режимов параметров. Инструкция routine_value проверяет соответствие сигнатуре целевой подпрограммы, call_value проверяет типизированный стек аргументов и вызывает обычный кадр VM. Значение хранит идентификатор нативной подпрограммы; адреса .NET, Python и поиск типов во время исполнения отсутствуют. Переменные, результаты, var/out, массивы, List и поля записей сохраняют этот тип. Цель вызова фиксируется до вычисления аргументов, nil проверяется после их вычисления; равенство именованных значений сравнивает цель. Лямбды и захваты реализованы в текущем профиле, multicast пока не реализован; передача процедурного значения в существующие операции последовательностей и TrueTable реализована.

Короткая запись процедурных типов (`T -> U`, `(T,U) -> V`, `() -> T`, `T -> ()`, `() -> ()`) разбирается в тот же SyntaxType callable и не добавляет динамического режима. ASCII -> и Unicode U+2192 нормализуются одним токеном; позиции остаются байтами UTF-8 и столбцами UTF-16. Стрелка правоассоциативна, вложенные сигнатуры и списки до 16 параметров сохраняют обычную проверку зависимостей типов. Стрелка в выражении разбирается как лямбда с отдельной проверкой параметров и результата.

Библиотечные обратные вызовы принимают как прежний идентификатор именованной функции, так и отдельное типизированное процедурное значение. Новые инструкции проверяют конкретную сигнатуру callable, источник и результат; существующий путь именованных вызовов сохранён. Ленивые SequenceState удерживают выбранное значение, а не переменную, и каждый курсор использует общий механизм VM. Для Zip nil проверяется в начале тела итератора, до GetEnumerator даже пустого источника; для LINQ-преобразований и запросов проверка происходит при вызове после вычисления аргументов. TrueTable сохраняет значение в локальном временном слоте и вызывает его проверяемой инструкцией call_value. Процедурное значение может содержать типизированное окружение замыкания.

Лямбда связывается до исполнения как скрытая подпрограмма с конкретной сигнатурой, собственными локальными переменными и списком захваченных ячеек. Захваты распространяются через вложенные окружения; var/out отвергаются как в исходном анализаторе. Результат берётся из контекста/аннотации либо первого типизируемого Result/Exit(value); общего вывода типа из разных ветвей пока нет. Верификатор проверяет единственного владельца каждого локального слота, доступность захватов и запрет прямого call_user к захватывающей подпрограмме. Для повторных объявлений захваченной переменной генератор выдаёт fresh_local, сохраняя отдельные ячейки разных входов в блок. VM удерживает окружение через shared_ptr<Cell>, передаёт его в обычный кадр и использует тот же бюджет исполнения. Слабый реестр окружений сначала удерживает выжившие замыкания, затем очищает рёбра захватов без выделений памяти при завершении VM, включая ошибку. Тесты повторяют нормальный и ошибочный запуск с циклами через записи/функции для проверки LSan. Инкрементальный сборщик циклов и захват управляющих переменных циклов остаются в плане.

Генераторы SeqGen/ArrGen/MatrGen/Iterate/SeqWhile используют одну проверяемую инструкцию generator с типом выхода, видом перегрузки и статическим callable-типом. HIR сохраняет порядок вычисления аргументов; верификатор проверяет формы параметров, начальные значения, ранг и предикат. VM переносит аргументы в собственный вектор до реентерабельного вызова. Для ленивых генераторов дескриптор хранит функцию и копии начальных значений, каждый sequence_begin создаёт отдельный GeneratorState. Значения выдаются через общий sequence_resume/sequence_at без материализации и без сокращения Count по известному размеру. Рекуррентный бинарный курсор сохраняет новый элемент и сдвигает пару только после продолжения с предыдущего yield. Индексный SeqGen проверяет count+from-1 при создании; ArrGen проверяет i+from поэлементно. Начальные элементы и нулевые размеры сохраняют исходное время nil-проверки. Для нулевой размерности MatrGen не обходит пустые строки. RuntimeError включает двуязычные ограничения count>0 и count>=2. Полное разрешение generic-перегрузок и пользовательские yield пока не перенесены.

Cartesian использует типизированные инструкции объединения источников с теми же контрактами сигнатур, что Zip, и отдельный курсор вложенных циклов. На каждом уровне хранит IEnumerator, следующий индекс и копию Current; внутренний курсор открывается заново при следующем внешнем значении. Проверка nil функции предшествует открытию внешнего источника, внутренние nil не читаются при пустом внешнем. Общий счётчик работы ограничивает и циклы без выдачи элементов. CartesianPower имеет отдельный статический контракт источник/буфер/результат: массив удерживается по ссылке, sequence/List материализуется при вызове, string сохраняет преобразованные символы. Курсор проверяет n и длину при первом продвижении, хранит ограниченный индексный вектор и выдаёт новый массив либо UTF-16 строку без вычисления мощности произведения. Метаданные проверяют ранги и совпадение типов элементов; записи копируются, вложенные ссылки остаются общими.

Combinations/Permutations используют тот же статический контракт источник/массив/выход, что CartesianPower, и отдельный CombinatorState. Курсор сохраняет индексный вектор по позициям, буферы результатов и выбранное сочетание для частичных перестановок. Каждый yield копирует строку результата; записи копируются, вложенные ссылки разделяются. Ширина и nil проверяются в исходном порядке, пустая полная перестановка сохраняет последующую ошибку NextPermutation на пустом индексе. Нативный NextPermutation меняет значения integer-ячеек без перестановки самих ячеек; ложный результат не разворачивает последнюю перестановку. Переносы индексов, копирование и поиск опорной позиции имеют ограничение работы и отмену; верификатор фиксирует ранг, элемент, режим и типы стека до исполнения.

Индексные и матричные представления используют инструкцию array_view: тип источника, вид операции, статический тип результата и необязательный callable-предикат. Верификатор проверяет ранг, элемент, арность и координатные параметры до исполнения. Plain Indices строит Range по немедленно вычисленной длине; остальные представления создают отдельный ArrayViewState на перебор, сохраняют Current и верхнюю границу. List читается по индексу без версии, что сохраняет рост/сокращение исходного индексного цикла. Матричный nil-предикат проверяется при первом продвижении до источника, одномерный — только при фактическом вызове. Tuple-поля для координат типизированы, записи копируются, вложенные ссылки сохраняются. Обход без совпадений имеет отдельный счётчик работы и отмену, а SequenceDepthGuard восстанавливает глубину при ошибке.

Операции Row/Col и группы строк/столбцов имеют одну проверяемую инструкцию matrix_operation с конкретным типом матрицы, массива-строки, результата и видом операции. SetRow/SetCol нормализуют последовательность в typed ToArray до инструкции, сохраняя порядок вычисления аргументов и ошибки материализации. Runtime проверяет nil массива-замены до индекса, отрицательный индекс до Self, затем границы и длину. Swap/Set записывают существующие Cell через Values.write, поэтому var-ссылки на поля записей сохраняются. Лексер отмечает escaped-имена отдельно от ключевых слов; SyntaxType.named отделяет псевдонимы &array/&record и другие имена от структурных описаний типов.

IniFile uses an opaque native reference type with a fixed ini_call method contract; all declared public constructor/property/read/write signatures are bound and verified before execution. Private source fields and helpers are inaccessible across the library boundary. IniState holds only a filename and sorted typed sections/string values, avoiding dynamic System.Collections objects. Shared en-US cultural comparison preserves key ordering/equality and first spelling. Source parse rules and exception/Close placement are retained; native execution guards propagate. Existing Text supplies per-execution cwd, DefaultEncoding, BOM-aware streaming, writer/newline/sharing rules and deterministic cleanup. Explicit Save resolves the original path again, with no destruction-time persistence. Metadata disallows bypassing the typed constructor; reference copies and nil use existing Values behavior. Inheritance, inherited Object methods and general source-unit interoperability remain pending, so this module is tracked as partial.
